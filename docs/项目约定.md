### P0-1 落盘安全边界

**背景**：生成目录是青蔓**唯一会写用户磁盘**的动作。当前实现（`src/server/routes.py` 的 `generate`）只校验 `target` 是非空字符串，**无任何路径约束**；`dryRun` 也来自请求体，服务端不强制。任何请求都能让它在 `C:\Windows` 下建目录树，前端弹窗属 UI 层、可绕过。

**规则（必须落在服务端 `config.py` + `dtree_core.py`，不得只做前端限制）**

| 编号 | 规则 | 说明 |
|---|---|---|
| R1 | **路径规范化** | 一律 `Path(target).expanduser().resolve()` 后再校验；拒绝含 `..` 逃逸的结果。禁止在校验前使用未规范化的路径 |
| R2 | **盘根黑名单** | 拒绝 `target` 为盘根（`C:\` / `D:\` …），要求至少两级 |
| R3 | **系统目录黑名单** | 拒绝 `%SystemRoot%`（含 `System32`）、`Program Files`、`Program Files (x86)`、`ProgramData` |
| R4 | **用户目录黑名单** | 拒绝 `%USERPROFILE%` 本身、`Desktop` / `Documents` / `Downloads` 的**根本身**（允许其子目录） |
| R5 | **项目自身目录** | 拒绝 `QingMan/` 及其父目录，防止工具改自己 |
| R6 | **规模阈值** | `plannedDirs + plannedFiles` 超过 `QM_MAX_NODES`（默认 500）时**服务端直接拒绝**，不依赖前端确认 |
| R7 | **覆盖策略** | 目录已存在 → **复用**；文件已存在 → **跳过、不覆盖、不比对内容**，计入 `existed`。响应须区分「新建 / 已存在」 |
| R8 | **永不删除** | 生成过程绝不删除任何既有文件或目录。与项目「只复制不删除」总原则一致 |

**验收方式**：`tests/` 中对 R1–R6 各有一条用例，命中黑名单须返回明确错误码（不是 500）。

**状态**：✅ **已实现**（2026-10-09，**V0.0.4**）。

| 层 | 落点 |
|---|---|
| 黑名单数据 + 辅助函数 | `config.py`：`resolve_path()` / `is_within()` / `_blocked_subtrees()` / `_blocked_roots()` / `BLOCKED_SUBTREES` / `BLOCKED_ROOTS` / `PROJECT_DIR_RESOLVED` / `MAX_NODES` |
| R1–R5 判定 | `dtree_core.check_target(raw)`（R1 `expanduser().resolve()`；R2 `len(path.parts) < 2`；R3 子树包含；R4 仅根本身；R5 项目自身或上级） |
| R6 规模阈值 | `dtree_core.build_tree()` 前置 —— 用 `count_tree()` 算**计划规模**，超 `QM_MAX_NODES`（默认 500）即拒绝；`dryRun` **同样拦截**（上限针对"计划"本身） |
| R7 / R8 | `build_tree()` 既有行为：目录已存在 → 复用并计入 `existed`；文件已存在 → **跳过不覆盖**；全程只 `mkdir` / 新建，**无任何删除调用** |
| 接线 | `routes.generate()` 调 `check_target()`；响应回填 `result["target"] = str(base)` |
| 错误码 | `error-codes.json` 新增 `targetInvalid` / `targetTooShallow` / `targetBlocked` / `targetReserved` / `tooManyNodes`（**全部 400，无 500**） |

**实测**：`tests/test_dtree_core.py` 的 `CheckTargetTests`（R1–R5）与 `BuildTreeTests`（R6–R8、生成内容 LF）；`tests/test_routes.py` 的 `GenerateGuardTests`；`tools/smoke.py` 三项边界用例 —— 盘根 → `targetTooShallow`、`C:\Windows\System32\evil` → `targetBlocked`、项目自身 → `targetReserved`，且**超限未落盘**。

**同轮一并处理的换行点**（属 §编码基线，见§P2 第 11 项）：`routes.py` 写 `data/editor.json`、`dtree_core.py` 写生成文件，均改为 `open(..., newline="\n")`。**顺带修掉一个真缺陷**：`save_editor()` 曾返回**小于盘上文件**的 `bytes`（Windows 下盘上是 CRLF），现两者一致并有单测断言。

### P0-3 双语与皮肤预留

**背景**：中英双语与多皮肤都在路线图内，但当前 UI 字符串**全部硬编码**（8 个 JS 文件均含中文直写，无取词函数），皮肤机制也未定义。等到 V0.1.x 再做，等于**重写全部 UI 模块与组件 CSS**。

**规则（现在只立约定，实现可延后 —— 但新写的代码必须遵守）**

| 编号 | 规则 |
|---|---|
| L1 | 所有**面向用户可见**的字符串必须经统一取词函数 `t(key)` 获取，**禁止在 UI 模块里直写文案** |
| L2 | key 命名：`<模块>.<元素>.<语义>`，如 `inspector.title`、`tree.menu.delete`、`toast.saved` |
| L3 | 过渡期 `t()` 可先返回中文常量；字典文件落位 `src/web/js/i18n/zh-CN.js`（后续加 `en-US.js` 即可切换） |
| L4 | CSS **只允许** `var(--qm-*)` 取色与尺寸，**禁止裸色值、裸尺寸**；新增变量必须先在 `tokens.css` 定义 |
| L5 | 皮肤 = 一组变量覆盖文件 `src/web/css/skins/<name>.css`；**组件 CSS 不得感知皮肤**（不写 `.skin-dark .btn` 这类选择器） |
| L6 | 语言 / 皮肤 / **界面折叠态**持久化于 `localStorage`，键名固定 `qm.lang` / `qm.skin` / `qm.genBar` |
| L7 | 违反 L1 / L4 的**既有**代码：`src/web/css/base.css` 第 53、55 行的硬编码 `#fff`（**实测 2 处**）—— **✅ 已清（V0.0.5）**：改 `color: var(--qm-on-accent)`，并在 `tokens.css` 新增该变量（浅色 `#ffffff` / 深色 `#0f1a16`）。`verify.py` 的「组件 CSS 无裸色值 §P0-3 L4」项已能守住回归 |
| L8 | **SVG 资源的着色方式**（2026-10-09 立）：项目内 SVG 一律经 ① CSS `mask` 取形状 或 ② 内联 `currentColor` 使用。**禁止 `<img src="*.svg">`** —— `<img>` 中的 SVG 是独立文档，`currentColor` 不继承，颜色只能写死在文件内部，违反 L4/L5。同理禁用跨文档 `<use href="*.svg#id">`（现代浏览器已不支持外部引用） |

**状态**：✅ **已实现**（2026-10-09，**V0.0.5** 全量取词化 → **V0.0.6** 补 `qm.genBar` 并扩 L6 守卫至三键）—— 由"部分落地"推进到全量。

| 规则 | 落地 |
|---|---|
| L1 | **主界面 + 帮助页 + 全部 8 个 JS 模块的文案零直写**。`verify.py` 三项把关：「主界面无硬编码中文」「帮助页无硬编码中文」「JS 文案经取词表 §P0-3 L1」（后者的判据是"除 `i18n/` 目录外，JS 中不得出现中文字符串字面量"） |

| L8 | 品牌标记继续走 CSS `mask` + `var(--qm-accent-ink)`，未引入 `<img src="*.svg">` |

### P0-4 版本控制分工（git + store 双层）

**背景**：`tools/` `docs/` `templates/` **既不入版本清单、按判据也不升版** —— 等于无历史，只靠人工时间线。随工具链增长会越来越难追溯。

**决策（2026-10-09 用户裁定）**：**引入 git 管理全项目**。

**分工**

| 机制 | 管什么 | 覆盖范围 |
|---|---|---|
| **git** | **过程历史**：什么时候、改了哪些行、为什么改 | **全项目**（含 `tools/` `docs/` `templates/`） |
| **`tools/store.py`** | **可交付版本的隔离与回退**：某个交付版本如何完整取回 | `src/` + `start.bat` + `VERSION` |

两者**不互相替代**：git 回答「改了什么」，store 回答「某个版本怎么取回」。git 的提交不替代 store 的 `commit`，反之亦然。

**`.gitignore` 约定**（只忽略确定性垃圾，其余全部纳入）

```
__pycache__/
*.pyc
*.pyo
store/.trash/
.vscode/
.idea/
*.swp
Thumbs.db
Desktop.ini
*.log
```

**红线**

| 编号 | 规则 |
|---|---|
| G1 | `store/` `versions/` `legacy/` **必须纳入 git** —— 它们是唯一的版本数据，不入库即无备份 |
| G2 | `settings`：项目级身份配置，不依赖全局（`git config --local`） |
| G3 | git 提交与 `store.py commit` **成对执行**：凡改动 `src/`，两者都要做 |
| G4 | 禁止 `git push --force` / `git reset --hard` / 删除分支等破坏性操作（与项目高风险清单一致） |

### P0-5 本地服务调用来源校验

**背景**：服务仅监听 `127.0.0.1`，但**监听回环 ≠ 只有本机能调用**。实测（2026-10-09）`app.py` 全文无任何来源校验，`do_POST` 仅比对路径 —— 本地任意网页、乃至公网页面经 DNS rebinding，都可盲发 `POST /api/generate` 触发磁盘写入。CORS 只限制「跨域**读取**响应」，无法阻止「跨域**发起**请求」（简单请求不预检、响应读不到但副作用已发生）。

这是「**谁能触发**」的闸门，逻辑上**先于 P0-1 的「能写到哪」**。

**规则（全部在 `app.py` 统一中间件 `_guard()` / `_guard_write()` 实现，不得散落到各路由）**

| 编号 | 规则 |
|---|---|
| S1 | **Host 白名单**：`Host` 头的 host 部分必须属于 `config.ALLOWED_HOSTS`（默认 `127.0.0.1` / `localhost` / `::1`），否则 403 `hostRejected`。**不比较端口** —— Host 由浏览器依据 URL 生成，攻击者无法把它伪造成回环名 |
| S2 | **Origin 严格同源**：若请求带 `Origin`，必须同时满足 ① scheme = `http` ② host 在白名单 ③ **port = 实际绑定端口**，否则 403 `originRejected`。`Origin: null`（沙箱 iframe / `data:` / `file:`）因 scheme 为空同样被拒 |
| S3 | **写操作防护头**：`POST` 必须携带 `X-QingMan: 1`，否则 403 `missingGuardHeader`。跨站页面携带自定义头必然先触发 CORS 预检 |
| S4 | **不响应预检**：`do_OPTIONS` 一律 403 `methodNotAllowed`，且**不返回任何 `Access-Control-Allow-*` 头** —— 预检失败会使浏览器放弃后续的实际请求 |
| S5 | **只读请求不强制 S3**：`GET`（含静态资源）不加防护头（`<link>` / `<img>` 无法自定义头），仅受 S1/S2 约束；S3 只叠加在写操作上 |

**为何能防 DNS rebinding**：攻击者把自有域名解析到 `127.0.0.1` 后，浏览器发出的 `Host` 仍是**攻击者域名** → 不在白名单 → 被 S1 拒绝。

**前端配套**：`src/web/js/core/api.js` 的 `DEFAULT_HEADERS` 固定携带 `X-QingMan: 1`；同源请求携带自定义头**不触发预检**，故无额外开销。

**验收**：沙盒冒烟 **25 项全通过**（正常放行 4 / Host 拒绝 5 / Origin 拒绝 5 / OPTIONS 1 / 防护头 3 / 功能未回归 6，另含「被拒请求均未落盘」断言）。

**状态**：✅ **已实现**（2026-10-09）。改动文件：`app.py`（`host_of()` + `_guard()` + `_guard_write()` + `do_OPTIONS`）、`config.py`（`ALLOWED_HOSTS` / `GUARD_HEADER`）、`error-codes.json`（4 个新码）、`api.js`。

### P0-6 同版本多修订（不升版也要留回退点）

**背景**：升版判据是「改 `src/` 才升版」，但存在**用户裁定不升版却改了 `src/`** 的情况（如 2026-10-09 的 N1）。旧 `do_commit` 遇**已存在版本直接跳过** → 这类改动**无 store 回退点**，只剩 git。而 git 回答「改了什么」，**不能替代**「按版本完整取回」——两者分工见 §P0-4。

**规则（全部落在 `tools/store.py`）**

| 编号 | 规则 | 说明 |
|---|---|---|
| M1 | **清单命名固定**：`versions/<版本>/MANIFEST.json` 为**基线 r1**；`MANIFEST-r<N>.json` 为第 N 次修订（N ≥ 2）。**已存在的清单文件永不覆盖** | 与「`versions/` 只增不改」一致 |
| M2 | **同版本追加而非跳过**：`commit` 遇同版本已有清单时，追加下一个修订号；**仅当**内容指纹与最新修订完全一致才跳过，避免产生空修订 | 这是本条约的核心修正 |
| M3 | **双链留痕**：`parentManifest` 记同版本内上一清单文件名；`parent` 仍指跨版本链 | 两条链各司其职 |
| M4 | **引用语法**：`V0.0.1` = 该版本**最高修订**；`V0.0.1@r1` / `V0.0.1@r2` = **精确修订**。`checkout` 与 `diff` 均须支持 | 省略 `@rN` 即取最新 |
| M5 | **git 成对留痕**：store 追加 rN 时，git 提交用同一 `--note`，并打 tag `V<版本>-r<N>` | 与 §P0-4 §G3 一致 |
| M6 | **每修订一条明细**：`CHANGELOG.md` 对应版本段落下写 `### r<N>` 小节 | 版本号不升，但改动必须可查 |

**升版与修订的选择**：改 `src/` 时二选一 —— ① **升版**（新版本号，修订自动从 r1 重开）；② **不升版**（同版本内追加 rN）。**两者都必须先 `commit` 再继续改动**，「先改再看」不可接受。

**验收**：沙盒 10 项断言全通过（r1 生成 / r2 追加 / 无变化跳过 / log 双行 / diff 精确到修订 / 省略 `@rN` 取最新 / 精确回退到 r1 / 不存在修订报错 / 回收区收存 / `fsck` 0 损坏）。

**状态**：✅ **已实现**（2026-10-09）。

### P0-7 编辑态数据契约与持久化

**背景**：编辑态（内存里的目录树）此前**只活在页面内存中**，刷新即全部丢失（`main.js` 每次用硬编码示例重建）；同时 id 由「时间基 + 计数」派发、**计数随页面重载归零** —— 一旦引入持久化，恢复出来的既有 id 与新派发的 id 就可能撞号。这两件事必须一起解决。

**为什么不选 `localStorage`**：它按 **origin**（scheme + host + **端口**）隔离，而本服务端口自 `PORT_START`（8765）起**扫描**、并不固定 —— 端口一变 origin 就变，草稿会**静默消失**，且用户不会收到任何提示。故选后端文件，跨端口稳定。

| 编号 | 规则 |
|---|---|
| E1 | 编辑态文档的结构以 `src/shared/schema.json` 的 `editorDocument` / `editorNode` 为准；前后端**同一份定义**，不得各写一套 |
| E2 | 落盘位置固定为项目根 `data/editor.json`。`data/` 属**用户数据** → 进 `.gitignore`，**不进版本清单、不进过程历史** |
| E3 | 服务端对 `PUT /api/editor` 的内容**必须重新校验**（结构 / 命名 / id 唯一 / 同层不重名 / 规模上限），不合法即**拒写**；**不得信任前端** |
| E4 | 写入必须是**原子替换**（临时文件 → `os.replace`），避免中断留下半截文档 |
| E5 | 文档损坏时**不得静默当作空文档**（那会悄悄覆盖用户数据）→ 报 `editorCorrupt` 并保留原文件 |
| E6 | 保存模式为**自动保存**（防抖 800ms）＋ `Ctrl+S` 立即保存；顶栏保存状态 chip 须始终反映真实状态（未保存／保存中／已保存 HH:MM／保存失败） |
| E7 | id 唯一性靠**集合判定**，不靠概率：`uid()` 派发前查已用集合；**从文档恢复后必须先 `reserveIds()` 再转换**；`assertUniqueIds()` 用于校验与测试断言 |
| E8 | 同层节点名**不得重复**，比较**大小写不敏感**（落盘目标多为 Windows 文件系统）；新建与重命名均须拦截 |
| E9 | 编辑态文档与「一键生成」互不写入：生成只读内存树并写目标目录，**不读也不写** `data/editor.json` |

**验收**：`verify.py` 的「编辑态契约」「编辑态接口与错误码」两项；固定时钟下「不 `reserve` 必撞号 → `reserve` 后不撞号」的对照断言；三类非法文档 400 拒写且不覆盖既有内容。

**状态**：✅ **已实现**（2026-10-09，**V0.0.2**）。改动文件：`tree-model.js`（`uid` / `reserveIds` / `assertUniqueIds` / `hasSiblingName` / `toDocumentNode` / `fromDocumentNode`）、`main.js`、`api.js`、`index.html`、`config.py` / `dtree_core.py` / `routes.py` / `app.py`、`schema.json`、`error-codes.json`。

## 四、本文件的维护规则

1. **每条约定必须可验收** —— 要么有工具实现，要么有测试用例，要么有明确的检查动作。**无实现、无验收的条目不得写入**（教训见错误笔记 §三.7「承诺了却没实现」）。
