## 二、P2 清单（7 项 · 建议修）

### A-P2-1 · `load_editor` / `load_template` 漏捕 `UnicodeDecodeError` → 请求线程裸崩

- **位置**：`src/server/routes.py` L127-130（`load_editor`）、L305-308（`load_template`）。
- **现象**：两处的 `path.read_text(encoding="utf-8")` **只捕 `OSError`**；文件内容为**非法 UTF-8**（如用户用别的编码编辑过）时抛 `UnicodeDecodeError`（属 `ValueError`，**不是** `OSError`）→ 冒泡到 `app.py` 的 `do_GET`（L152-159 **无通用兜底**）→ 500 无响应体 + stderr traceback。
- **实证**（临时目录，`data/editor.json` 写 GBK）：
  ```
  -> 抛出: UnicodeDecodeError: 'utf-8' codec can't decode byte 0xb2 in position 19: invalid start byte
  ```
- **内部不一致（关键）**：同项目 `list_templates`（L274）与 `rename_template`（L516）捕 `(OSError, ValueError)`（**不会漏**）；`tools/verify.py` 自身在 L264/L377 亦用 `except (OSError, UnicodeDecodeError)`。—— 即**项目已知该模式，唯此两处漏写**。
- **建议**：两处改 `except (OSError, UnicodeDecodeError)`（或统一 `(OSError, ValueError)`），并给 `do_GET` 补一条 `except Exception` 兜底（对齐 `do_POST`）。
- **影响面**：`GET /api/editor`、`GET /api/templates/<name>`。

### A-P2-2 · `validate_segment` 未拒绝尾随空格 / 尾随点 → 记录名 ≠ 磁盘名

- **位置**：`src/server/dtree_core.py` L65-81（`validate_segment`）＋ L236（`build_tree` 用**原始** `name` 落盘）。
- **现象**：`s = name.strip()` 仅用于**校验**，落盘仍用原始 `name`。`"a "` / `"abc."` 均判**合法**；Windows 文件系统会**规范化**掉尾随空格/点 → 磁盘实际名与记录名不符。
- **实证**：
  ```
  validate_segment('a ')   -> (True, '')
  validate_segment('abc.') -> (True, '')
  build_tree({"a b ": {}, "c.": {}})
    记录 createdDirs: [...\a b , ...\c.]
    实际磁盘名     : ['a b', 'c']
  ```
- **影响**：`createdDirs`/`createdFiles`/`existed` 报告失真（用户照着报告去点会找不到）；`validate_document` 的同层重名检测（`strip().lower()`）与磁盘规范化口径不一致。
- **建议**：在 `validate_segment` 中拒绝 `s != name.strip()`（有首尾空白）或 `s.rstrip('.').rstrip(' ') != s`（尾随点/空格）；新增错误码（如 `segmentTrailing`）。
- **注意**：属行为变更，须同步前端提示与 `tests/test_dtree_core.py`。

### A-P2-3 · `validate_ico` docstring 承诺「宽高值域校验」但代码未实现

- **位置**：`src/server/routes.py` L596-635。docstring（L600-601）明列「宽高 0(=256)/16/32/48/64/128/256、色彩数 0」，但**代码只校验了 `colors`、`planes`、`bpp`，对 `w`/`h` 只读取、从未校验值域**。
- **性质**：名实不符（守卫/文档承诺未兑现）—— 与《审查报告_工具链_20261010》P2-14（`build_tree` 规模项名实不符）同族。
- **影响**：安全影响低（仍须过 PNG 帧结构校验），但违背项目「守卫必须名副其实」的既有纪律。
- **建议**：补 `if w not in (0,16,32,48,64,128,256) or h not in (...): raise fail()`；或**如实改 docstring** 为实际行为。二选一，勿留不一致。

### A-P2-4 · `_load_error_codes()` 模块级执行且漏捕编码错误 → 服务无法启动

- **位置**：`src/server/dtree_core.py` L33-45（`read_text` 只捕 `OSError`；`_ERROR_CODES = _load_error_codes()` 在**模块顶层**执行）。
- **现象**：`src/shared/error-codes.json` 若为非法 UTF-8 → 抛 `UnicodeDecodeError` → **import 阶段崩溃** → `python -m server` 起不来（比 A-P2-1 更重：全站不可用）。
- **建议**：同 A-P2-1 扩捕获范围；或把加载包进 `try/except Exception` 并回落空表（`message()` 已有「未命中回显键名」兜底）。
- **触发条件**：苛刻（文件是项目资产），故与 A-P2-1 同批处理即可。

### B-P2-1 · 前端「新建 / 重命名」不校验名字合法性 → UI 先「成功」、保存时才失败

- **位置**：`src/web/js/main.js` L397-421（`doAddChild`）、L423-449（`doRename`）。两处**只查同层重名**（`hasSiblingName`），**不校验**非法字符 / 保留名 / 超长。
- **实证**：全项目 `src/web/js/` 内**无任何**名字合法性校验函数（`grep` 仅命中 i18n 文案与注释）。
- **现象**：用户输入 `a/b` → UI 立即显示新名「成功」→ 800ms 后自动保存被后端 `segmentInvalid` 拒绝 → 只弹「保存失败」。刷新后名字回退 —— **前后端校验不对称**。
- **建议**：把后端 `validate_segment` 的判据**镜像**一份到前端（`tree-model.js` 导出 `validateSegment`），在 `doAddChild`/`doRename` 里**即时**拦截并本地化提示（`err.segmentIllegalChar` 等文案**已在 i18n 里**，直接复用）。
- **备注**：后端兜底在，故非数据损坏，属可用性 + 一致性缺陷。

### C-P2-1 · `createSkinPicker` 未监听 `qmlocalechange` → 换语言后皮肤下拉不刷新

- **位置**：`src/web/js/ui/skin-picker.js` L20-37（**无** `qmlocalechange` 监听）；对照 `src/web/js/ui/lang-picker.js` L41 **有** `document.addEventListener('qmlocalechange', fill)`。
- **实证**：`src/web/js/i18n/skins.js` 的 `label` 是**取词键**（`skin.1`…`skin.15`）→ 皮肤名随语言变化，故**必须**在语言切换时重填 `<option>`。
- **现象**：主界面切语言后，皮肤下拉仍是旧语言文案（须刷新页面才更新）；`lang-picker` 自身正常 —— **两个 picker 行为不一致**。
- **建议**：`createSkinPicker` 抽出 `fill()` 并注册 `qmlocalechange`（与 `lang-picker` 同构）。

### D-P2-1 · 「组件 CSS 无裸色值」守卫**只查 `#hex`** → 2 处裸 `rgba()` 逃逸

- **位置**：`tools/verify.py` L556 `HEX_LIKE = re.compile(r"#[0-9a-fA-F]{3,8}\b")`（L563 检查项「组件 CSS 无裸色值 §P0-3 L4」）。
- **现象**：判据**只匹配 `#hex`**，不匹配 `rgb()/rgba()/hsl()` → `src/web/css/base.css` **2 处裸色值逃过守卫**：
  - L75 `.btn-primary` 的 `inset .5px .5px 1px rgba(255, 255, 255, .18)`（对照 `.btn` L46 用的是 `var(--qm-edge-hi)`）；
  - L82 `.btn-primary:active` 的 `inset 1px 1px 3px rgba(0, 0, 0, .25)`（对照 `.btn:active` L60 用的是 `var(--qm-inset)`）。
- **性质**：**守卫盲区**（检查项名「无裸色值」> 实际「无裸 hex」）—— 与 `tools/` 审查里的「换行守卫盲区」（P2-1）同族。
- **建议**：① 判据扩为 `#hex | rgb(a)?( | hsl(a)?(`；② 上述 2 处改走变量（复用 `--qm-edge-hi` / `--qm-inset`，或新增 `--qm-edge-hi-strong`）；③ 修后**反向验证**（注入 `rgba` 须 FAIL）。
