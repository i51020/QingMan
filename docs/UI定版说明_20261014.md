| 层 | 元素 | 形态 | 内容来源 |
|---|---|---|---|
| 遮罩 | `#scrim` | 全局单例 | — |

| M2 帮助 | `#dlgHelp` | `modal-lg` | 左目录 `#dlgHelpToc` + 右正文 `#dlgHelpDoc`，由 `js/ui/help-doc.js` 渲染 |

| M6 皮肤 | `#popSkin` | `popover` | `js/ui/skin-picker.js` 按 `swatch` 渲染 `.sw-card` 到 `#skinGrid` |

**弹层物理**：

- `modal`：居中 + 遮罩 + 焦点陷阱 + `#app` 置 `inert`（背景不可点）；
- `popover`：贴触发器下沿 + 无遮罩 + 点外部关闭；
- 三条关闭路径统一由 `ui/layer.js` 接线；`hidden` 由 `.layer[hidden]` 提升到真正 `display:none`
  （否则只是 `opacity:0`，仍可点）。

**z-index 阶梯**：`#scrim` 900 → `.layer` 1000 → `#ctxMenu` 1100 → `.toast-host` 1500。

**弹层必须置于 `#app` 之外**：`#app` 在弹窗打开时被置 `inert`，弹层若在其内会一并失去交互。

**为什么帮助 / 支持改弹窗**：主界面内存里可能正握着一棵尚未落盘的目录树，
**同标签跳转会丢编辑态**（见 `docs/项目约定.md` §P0-3）。弹窗在原页面就地开合，不打断编辑。

**为何在接线处 `preventDefault()`**：按钮位于 `<label>` 内，浏览器会把点击**转发**给 label 关联的输入框 —— 若不拦，原生框弹出前输入框会被顺手聚焦（收起键盘态时视觉上像「没反应」）。

**语义边界（实测，非推测）**：后端 `_ask_directory()` 是 `filedialog.askdirectory(mustexist=True)`，且**不接受 `initialdir`** —— 故点选**只能选已存在目录**，且打开时**不定位**到 `#inTarget` 现值。这是复用途经的既定代价，已记入《项目手册》§9.2-9；日后若需「定位当前值 / 允许新建不存在的路径」，再评估端点加参（B 路线）。

### 7.2 两处设计抉择

**① 起点选项取「当前模板库」，而非写死内置 P0 文件名。**
模板库是可绑定的（`QM_TEMPLATES_DIR` env > settings > 默认 `templates/`，见 `config.templates_dir()`）。若把「内置 P0」写死成 `P0_空白项目模板.json`，用户一旦把库绑到外部目录，该选项必然失效。改为「空白 + 库中每一套」后：默认态库里唯一一套就是 P0（**行为与预期一致**），换库后自动跟随。顺带规避了「JS 里硬编码中文文件名」会触发的 7b 守卫。

**② 落盘后不自动载入编辑器。**
载入会**丢弃内存里那棵尚未落盘的树**（《项目约定》§P0-3）—— 这正是 B 组把帮助 / 支持从新标签改为应用内弹窗要规避的同一类事故。故新建后只刷新列表；要编辑它，在列表里点它即可（那条路径本就有未保存确认）。

### 7.3 复用的后端契约（**零改动**）

| 端点 | 用途 |
|---|---|
| `POST /api/templates` | 落盘 `saveTemplate({name, description, tree})`；同名默认拒写（`templateExists`），用户确认后带 `overwrite:true` 覆盖且旧模板入 `templates/.trash/` |
| `GET /api/templates/<name>` | 「起点＝某模板」时取其 `tree` 作骨架 |
| `GET /api/templates` | 填起点下拉（替代写死的内置模板名） |

**空白起点的合法性已在后端核实**：`save_template` 对 `tree` 只做 `isinstance(dict)` + 规模上限，**无下限**；`count_tree({})` → `(0,0)`，故 `tree: {}` 可落盘（＝只有根节点、无子节点的模板）。

### 7.4 新增 CSS 通用类的由来

`base.css` 里原有明确约定：「日后若新增不在 `.topbar-select` 内的 `<select>`，须另配箭头」。弹窗里的「起点」下拉正是**不在顶栏**的第一例 —— 处置方式是**抽共用选择器**（`.topbar-select::after, .select-wrap::after`），而非再抄一遍箭头规则（后者迟早漂移）。

|---|---|---|
| 1 | **Soft（软光）正式化为「新默认」** | 不再是「可整块摘除的独立层」，而是**唯一的设计语言 / 基础层**：`<html data-soft>` 属性开关**移除**（三页去属性），`soft.css` **53 处**规则前缀 `html[data-soft]` → `html`，**无开关、直接生效** |

### 8.2 形态归一（实测依据）

15 款皮肤的**变量集完全相同（各 23 个）**，且 `--qm-shadow-raise` / `--qm-inset` 的**唯一取值数 = 1** —— 它们是**同一份形态的 15 份冗余拷贝**。故：

- 15 款皮肤**剥离**这两个变量（**23 → 21**），形态表达式**上移 `tokens.css`**、其值引用**皮肤影色变量**（`var(--qm-shadow-dark)` 等）。
- **零视觉差异的根据**：`var()` 在**使用点**解析 → 行为等价。**等价性实证 39 组零差异**（15 皮肤 × 2 + 9 语法变量）。
- 新增 **6 个形态语法变量**（`--qm-card-edge` / `--qm-topbar-shadow` / `--qm-layer-shadow` / `--qm-pop-shadow` / `--qm-qr-shadow` / `--qm-btn-edge`），`soft.css` 从此**不含 `\d+px` 字面量**。

### 8.3 交互态特异性反转（本轮最大坑，见《错误笔记》§三.67）

`[data-soft]` 是**属性**选择器 (0,1,0)、`html` 是**元素**选择器 (0,0,1)。**去属性使 soft 全部规则特异性整体降一档**（`html[data-soft] .x` (0,2,1) → `html .x` (0,1,1)），于是：

- `layout.css` 的 `.tpl-item:hover` (0,2,0) → 反超，**hover 泄漏旧设计的 `--qm-accent-soft` 灰底 + `--qm-accent` 描边**；
- `base.css` 的 `input[type="text"]:focus` (0,2,0) → 反超。

**关键盲区**：`getComputedStyle` 在**无鼠标**环境永远进不了 `:hover` —— **静态 564 元素探针全绿，却藏 34+4 处交互态回归**。定位法：把 `:hover` / `:active` / `:focus` **重写为同特异性的类**、全域施加、取计算值（无头逼出交互态层叠）。⚠ `:focus` 重写须用 `/:focus(?![-\w])/`，否则截断 `:focus-visible` 成非法选择器（**静默失效**）。

**补丁（已写进 `soft.css` 第 7 / 9 节，守卫 7d-6 连同断言）**：

```css
/* 第 7 节：压制 layout.css 的 .tpl-item:hover（(0,3,1) > (0,2,0)） */
html .tpl-row .tpl-item:hover { background: transparent; border-color: transparent; }

/* 第 9 节：focus 描边与 base.css 及 soft 自身取值一致（改善，非回归；另有 outline 兜底） */
html input[type="text"]:focus,
html select:focus,
html .prop-input:focus { border-color: var(--qm-accent); }
```
