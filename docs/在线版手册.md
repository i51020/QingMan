## 一、在线版是什么

青蔓的核心动作是**把目录树写到用户自己的磁盘**。这件事只能发生在用户机器上，因此「在线版」并不是把本机程序搬到云上，而是**换了一条写盘通道**：

| | 本机版 | 在线版 |
|---|---|---|
| 谁在写盘 | 本机 Python（`http.server`） | **浏览器**（File System Access API），用户当场点选文件夹 |
| 目标位置怎么给 | 输入框填路径 | **系统目录选择器**（不能填路径） |
| 数据存哪 | `<项目根>/data/editor.json` + 5 份轮转备份 | 浏览器 `localStorage` |
| 模板库 | 磁盘目录（可绑定外部目录、2.5s 轮询） | 浏览器存储（内置空白模板 + 在线新增） |
| 需要的运行时 | Python 3.8+（或随包 `runtime/`） | 无，只要浏览器 |
| 浏览器要求 | 任意现代浏览器 | **Edge / Chrome**（写文件夹需要 File System Access） |
| 桌面入口 | 点击 logo 生成 `.lnk` | **PWA 安装**（浏览器菜单「安装应用」） |

**一句话**：在线版是"真能用"的，只是写盘由浏览器代劳；不能填路径、不能选任意盘符，必须经过一次授权。

## 二、能力矩阵（2026-10-17 实测 43/43 通过）

| 能力 | 在线版 | 说明 |
|---|---|---|

| 模板：载入 / 另存 / 新建 / 重命名 / 复制 / 删除 | ✅ | 存在浏览器存储 |
| 模板：导入 `.json` / `.md` | ✅ | `.md` 由 **JS 移植的同一份文法**解析（与 Python 端逐字节等价） |

| **目标位置（选一次、生成直接用）** | ✅ | 点选后句柄存 IndexedDB 的 `targetDir`（与模板库分键）；预热后同步判断，生成不再弹框 |

| 打开系统目录（资源管理器） | ⛔ | 浏览器无法弹本机窗口；用目录选择器代替 |

## 三、它是怎么工作的

```
浏览器
├─ index.html / help.html / support.html        静态页面（与本地版同一份 src/web 产物）
├─ api/env.js · api/locales.js                  构建时生成的静态替身（首屏语言同步注入）
├─ js/md-template.js                            模板 .md 文法的 JS 移植（parse / render）
├─ js/online-store.js                          浏览器存储层：IndexedDB（目录句柄）+ OPFS（历史版本）+ 备份
│                                              另含模板列表的**唯一排序口径** `byFile`
├─ js/demo-backend.js                           浏览器内后端：拦截 fetch('/api/*') 就地应答
├─ js/online-ui.js                              「服务设置 → 在线版数据」五个按钮（含「安装到桌面」）
├─ js/pwa.js + sw.js + manifest.webmanifest      安装与离线
└─ downloads/QingMan-<版本>-portable.zip         本机版下载（帮助页给出入口）
```

**关键点：`src/` 一行都没为在线版改动。** 在线能力全部落在构建期注入的文件里，删除构建脚本即可回到纯本机形态。

### 3.1 浏览器内后端

`demo-backend.js` 用 `window.fetch` 拦截 **同源 `/api/*`**，按与 Python 端**同一套契约**应答：

| 方法 | 路径 | 在线行为 |
|---|---|---|
| GET | `/api/health` | 恒 200；`dataDir` 如实写"浏览器本地存储" |
| GET/PUT | `/api/editor` | 读 / 写 `localStorage['qm.demo.editor']` |
| GET | `/api/editor-backups` | 列 OPFS 里的快照（最多 5 份，新→旧） |
| POST | `/api/editor-restore` | 按 `id`（文件名白名单校验）读快照并写回当前文档 |
| GET | `/api/templates` | 内置 `P0_空白项目模板.json` + 用户在线新增 |
| POST | `/api/templates` | 另存为（同名需 `overwrite`） |
| GET/POST/DELETE | `/api/templates/<name>` | 载入 / 重命名 / 删除 |
| GET | `/api/templates-export/<name>?format=json\|md` | 返回 `{file,name,source,text}` |
| POST | `/api/templates/import` | `{filename, content, overwrite}`，`.md` 走 JS 解析器 |
| GET | `/api/templates-dir` | 已绑定时回真实目录名；权限失效回 `available:false` + `needPermission` |
| PUT | `/api/templates-dir` | **绑定**：仅接受「刚点选过、且名字对得上」的句柄（`applied:true`）；手填路径一律 `applied:false` |
| POST | `/api/templates-dir/pick` | **真弹目录选择器**，只回报目录名、**不落库**；点的是「目标位置 · 选择…」时改走 `pickTarget()`（记住目标，见下） |
| POST | `/api/open-dir` | `available:false`（浏览器打不开资源管理器） |
| POST | `/api/generate` | **真写**：已记住目标就直接写（不弹框），否则选择器 → 创建真实目录与文件；`dryRun` 只回清单 |
| POST | `/api/shortcut` | 400 `demoUsePwa`，文案指向"安装应用" |
| POST | `/api/launch-icon` | 收到 ICO 就**触发下载**（`exported:true`），不再假装存储 |
| GET | `/api/demo-backup` | 导出 `{file, text}`（`qm-demo-backup/1`） |
| POST | `/api/demo-import` | 导入备份 JSON，合并模板 |
| POST | `/api/demo-clear` | 清 `qm.demo.editor` / `qm.demo.templates` |

> **模板列表顺序由代码规定**：`readDirTemplates` 的结果统一过 `byFile` —— 按文件名
> （先比小写、仅大小写不同时再比原名）排序，与本机版
> `sorted(..., key=lambda q: (q.name.lower(), q.name))` **同口径**。
> 此前两条分支（真实目录 / 浏览器内模板）各自沿用底层顺序：`values()` 是文件系统的
> 枚举序、`Object.keys()` 是插入序，都不承诺稳定（2026-10-17 修：用户报告「排序总是变化」）。
> 附带效果：前端轮询签名是 `file|mtime|size` 按序拼接，排序稳定后签名也稳定，
> 不会再每 2.5s 重建一次列表。**改文件名当然会换位置**，那属于正常。

> **目标位置与模板库分键存放**：`targetDir` 只由「目标位置 · 选择…」写，`templatesDir` 只由
> 「选择目录 + 绑定」写。两者互不影响，且「清空本机数据」只忘记目标（模板库是只读素材，保留）。
> 生成时是否弹框，由**同步**的 `peekTarget()` 决定 —— 弹框必须在用户激活窗口内发起，中间不能夹 `await`。

> **「选择」与「绑定」是两步**（与本机版一致）：`pick` 只把句柄放进内存的 `pendingDir`，
> 前端确认后才发 `PUT`，此时 `commitDir(name)` 才写 IndexedDB。目标位置的「选择…」
> 复用同一个 `pick` 端点但**从不发 `PUT`**，故不会改掉已绑定的模板库
> （2026-10-17 修复：此前 `pick` 当场落库，选一次目标位置就把模板库改绑了）。
| GET | `/api/env.js`、`/api/locales.js` | **放行到静态文件**（这两条不是 RPC） |
| 其余 | `/api/*` | 400 `demoUnsupported`（宁可报错，也不让请求落到 404 页） |

### 3.2 写盘的三个硬约束

1. **必须同步发起**：`showDirectoryPicker()` 要在用户点击的同一轮调用栈里调用。先 `await` 别的东西再弹，浏览器会以 `NotAllowedError` 拒绝。
2. **失败要分清**：`AbortError` = 用户取消；`NotAllowedError` = 未授权；无该 API = 浏览器不支持（提示换 Edge / Chrome 或下载本机版）。三者各有文案，绝不静默。
3. **空目录合法**：`{}` 是真空目录，不是空树；只有**根为空**才拒（`templateEmpty` / `treeMissing`）。

### 3.2.1 读写必须同源（2026-10-17 修复）

**一句话**：**绑了真实目录，读和写都必须落到那个目录**。否则就是「存了却看不见」。

**此前的缺陷（用户报的 bug）**：绑定目录后，模板**列表**从目录读，而
`POST /api/templates`（新建 / 另存为）**恒写 `localStorage`** —— 于是新建的模板
**永远不会出现在目录里**。同一根因波及**四条写操作**：新建 / 另存为 / 改名 / 删除 / 导入。

**现行口径**（`templateSink()` 一处判定，五个端点共用）：

| 绑定状态 | 写入落点 | 列表来源 |
|---|---|---|
| 已绑定且已授权 `readwrite` | 真实目录（`getFileHandle({create:true})` → `createWritable()`） | 同一目录 `values()` |
| 已绑定但未授权 | **拒写**，返回 `templateNeedPermission`（提示重新授权） | 目录 |
| 未绑定 | `localStorage`（`qm.demo.templates`） | 浏览器内模板 |

**文件名净化**（`safeTemplateFile()`）：只认 `.json` / `.md`（缺扩展名补 `.json`）；
长度 ≤ 120；拒绝 `/ \ : * ? " < > |` 与控制字符；拒绝 `..` 开头与结尾空格
（Windows 会静默吃掉结尾空格 ⇒ 写进 A、读时找不到 A）。非法名返回 `templateNameInvalid`。

> **实测**（无头 Edge + 假可写目录）：新建 → `{ok:true, sink:"dir"}`，目录内容
> `旧模板.json, 新模板.json`，列表随即出现新条目；改名 / 删除同步生效；
> `../evil` 与 `payload.exe` 均 400 `templateNameInvalid`。

### 3.3 数据都存在哪

| 键 | 内容 |
|---|---|
| `qm.demo.editor` | 编辑态草稿（`{schemaVersion, savedAt, root}`） |
| `qm.demo.templates` | **未绑定目录时**在线新增/导入的模板（`{文件名: {name, description, tree, mtime}}`）；绑定后写盘，不再写这里 |
| `qm.lang` / `qm.skin` / `qm.inspMode` / `qm.launchIcon` | 偏好（与本机版同名同义） |
| IndexedDB `qm-demo` / `kv` / `templatesDir` | 绑定过的模板目录**句柄**（可结构化克隆） |
| IndexedDB `qm-demo` / `kv` / `targetDir` | 记住的**生成目标**句柄（**与模板库分键**；清空本机数据会忘记它） |
| OPFS `backups/editor-*.json` | 历史版本快照，保留最近 5 份 |

> 清理站点数据 = 清空草稿与在线模板。需要长期保存请导出模板或下载本机版。

## 四、构建

```bash
py -3 tools/build_static_site.py                      # 默认输出 dist/static-site
py -3 tools/build_static_site.py --out dist/makers-live
py -3 tools/build_static_site.py --os-locale en-US    # 首屏语言（静态版探测不到 OS 语言）
```

产物结构：

```
<out>/
├─ index.html · help.html · support.html     页面（已注入演示后端与提示块）
├─ api/env.js · api/locales.js               首屏语言静态替身
├─ css/ · js/ · assets/ · locales/           与本地版同一份资源
├─ js/demo-data.js                           版本号 + 内置空白模板
├─ js/md-template.js                         模板 .md 文法（JS 移植）
├─ js/demo-backend.js                        浏览器内后端
├─ js/pwa.js · sw.js · manifest.webmanifest  安装与离线
├─ icons/icon-192.png · icon-512.png         PWA 图标（纯标准库生成）
└─ downloads/QingMan-<版本>-portable.zip     本机版下载（缺包时自动跳过）
```

**构建会做什么**：复制 `src/web` → 复制 `locales/` → 生成两个 `api/*.js` → 注入 4 个脚本与 manifest → 生成图标 → 内置本机版包 → 在 `index.html` / `help.html` 注入在线版提示与下载入口。

> ⚠ 产物目录已存在时会**改名让路**（`<out>.old-<时间戳>`）而不是删除：本环境有批量删除保护，
> 且旧产物被上一个本地服务占用时 `rename` 会失败并回落成"复制 + 删除"，报错离真因很远。

## 五、部署（EdgeOne Makers）

```bash
# 1) 安装 CLI（≥ 1.6.0；免登录发布需 ≥ 1.6.29）
npm install -g edgeone@latest

# 2) 登录（中国站）
edgeone login --site china

# 3) 构建到干净目录
py -3 tools/build_static_site.py --out dist/makers-live-v0311

# 4) 打包（排除 .edgeone/ 与残留 .env，文件位于 zip 根层级）并直传
py -3 - <<'PY'
import zipfile, os
src = 'dist/makers-live-v0311'
skip_dirs, skip_files = {'.edgeone'}, {'.env'}
with zipfile.ZipFile(src + '.zip', 'w', zipfile.ZIP_DEFLATED, compresslevel=6) as z:
    for root, dirs, files in os.walk(src):
        dirs[:] = [d for d in dirs if d not in skip_dirs]
        for f in sorted(files):
            if f in skip_files:
                continue
            p = os.path.join(root, f)
            z.write(p, os.path.relpath(p, src).replace(os.sep, '/'))
PY
PAGES_SOURCE=skills edgeone makers deploy dist/makers-live-v0311.zip -n qingman --json
```

> `.env` 是目录直发失败时 CLI 写入的 0 字节残留（"Pulling environment variables" 步骤）——
> 打 zip 前须排除，否则线上多一个根级空文件。

注意四条：

1. **必须打 zip 直传，不要目录直发**（2026-10-18 实测，取代旧口径「换新 `--out` 目录即可」）：
   EdgeOne 的静态构建器（StaticAssetsBuilder）把站点复制进 `.edgeone/assets` 后会**清理重来**，
   单次部署的删除量即超过本环境 node 安全删除垫层的批量阈值（50）⇒ 直接失败
   （`[safe-delete][SAFE_DELETE_BULK_CONFIRM_REQUIRED]`）。**全新 `--out` 目录同样触发**
   （2026-10-18 实测两次）⇒ 现口径：构建后打 zip（排除 `.edgeone/`）用
   `edgeone makers deploy <zip> -n qingman --json` 直传，绕开本地构建器；实测
   18.5 MB / 67 文件上传成功（约 35 s，不含打包）。
2. **预览域名要带 token**：`https://<项目>.edgeone.cool?eo_token=...&eo_time=...`。不带 token 访问任何路径（含静态资源）都会 **401 `eo_time missing`**；首次通过带 token 的链接进入后，浏览器会拿到 cookie，页面内相对链接（含下载）即可正常工作。
3. **18 MB 单文件可接受**：实测上传成功，发布耗时约 41s（不含包时约 35s），下载回来 18,278,428 B 且 zip 有效。
4. **不要用 curl 直接判断"站点挂了"**：带 token 的请求会 302 并种 cookie，这是预览网关的正常行为。

## 六、版本同步

- 版本号唯一来源是 `VERSION`；构建时读它写进 `manifest`、`sw.js` 的缓存名、`demo-data.js` 的版本字段。
- 下载包文件名固定为 `QingMan-<VERSION>-portable.zip`，构建器按当前 `VERSION` 去 `dist/` 找；**找不到就跳过下载入口**，不会挂一个坏链接。
- 发新版顺序：`release.py bump` → 重建便携包 → `build_static_site.py` → `deploy`。三者必须同版本，否则下载到的本机版与在线版不是同一版。

## 七、已知限制（写在明处）

| 限制 | 原因 | 用户会看到什么 |
|---|---|---|
| 不能填目标路径 | 浏览器不给绝对路径 | 目标框预置说明并置灰，位置由目录选择器决定 |
| 每次生成都要授权 | 浏览器安全模型 | 目录选择器弹窗 |
| Firefox / Safari 不能写盘 | 无 File System Access API | `demoFsUnsupported` 文案，指引换浏览器或下载本机版 |
| 没有桌面 `.lnk` | 网页无法创建指向本机程序的快捷方式 | 应用内「安装到桌面」由浏览器建真快捷方式（指向已安装应用）；另可导出 `.ico` |
| 目标只记「名字」 | 浏览器不披露绝对路径 | 输入框显示文件夹名；生成时用的是句柄，不需要路径 |
| 历史版本存浏览器 | OPFS 属站点沙箱，清站点数据即失 | 弹窗里能看能恢复；长期保存请导出备份 |
| 清站点数据会丢草稿 | 存 `localStorage` | 帮助页与在线版提示块均已说明 |

## 八、故障排查

| 现象 | 原因 | 处理 |
|---|---|---|
| 页面 401 `eo_time missing` | 访问的是预览域名却没有 token | 用带 `?eo_token=...&eo_time=...` 的完整链接进入 |
| 状态栏"未连接" | 演示后端没被注入（构建时缺文件） | 检查产物是否含 `js/demo-backend.js`，重新构建 |
| 状态栏正常但点生成报 `demoFsUnsupported` | 浏览器无 File System Access | 换 Edge / Chrome，或下载本机版 |
| 点生成报"没有拿到写入授权" | 用户在弹窗中拒绝 | 重新点生成并允许 |
| 语言选择器只有中英 | 未注入扩展语言包 | 属正常（在线版只带出厂两包） |
| 更新后仍是旧页面 | service worker 缓存 | 刷新一次即可（SW 取网络优先）；必要时清站点数据 |
| `[safe-delete]` / 部署失败 | 本地构建器清理 `.edgeone/assets` 超批量删除阈值（50）—— **全新目录同样触发**（2026-10-18 实测，旧口径「换新目录」已不足） | 打 zip（排除 `.edgeone/`）后 `edgeone makers deploy <zip> -n qingman --json` 直传，见 §五.1 |

## 九、与仓库其余部分的关系

| 文件 | 作用 |
|---|---|
| `tools/build_static_site.py` | 唯一构建入口 |
| `tools/web-demo/demo-backend.js` | 浏览器内后端（在线版全部 `/api` 行为） |
| `tools/web-demo/md-template.js` | 模板 `.md` 文法的 JS 移植（与 `dtree_core.py` 逐字节等价，16 套真实模板双向验证） |
| `tools/web-demo/make_icons.py` | PWA 图标生成（纯标准库，无 Pillow 也能出 PNG） |
| `docs/项目手册.md` | 本机版与工程约定（权威） |
| `docs/在线版手册.md` | **本文** —— 在线版的唯一权威描述 |

> 判定标准：**在线版的所有代码都在构建期注入**。若某天要让在线版影响 `src/`，先问一句"本机版是否需要"——
> 不需要就不要进 `src/`，否则两边的维护成本会一起涨。
