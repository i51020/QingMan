## 一、为什么现在不做

`routes.py` **62,374 B / 单文件上限 65,536 B** ⇒ 只剩 **3,162 B（4.8%）**。
`src/` 合计 **619,486 B / 总量上限 655,360 B（640K）** ⇒ 只剩 **35,874 B（5.8%）**。

⇒ **下一次往服务端加功能必撞线**。历史上已因同一原因拆过三次（`backups.py` / `templates.js` / `selection.js`），每次结论都是「**拆模块，不是放宽阈值**」。

## 二、为什么不是「搬一个文件」

三个障碍，逐一都有实证：

1. **会循环导入**：`_fail` / `_tmp_sibling` 等共享助手就住在 `routes.py` 里。若把模板族搬出去、让它 `from routes import _fail`，而 `routes.py` 又要把搬走的名字再导出回来 ⇒ **环**。⇒ 必须先抽公共模块。
2. **守卫锚死了函数体**：`verify.py` 有 **29 行**引用 `routes.py`，其中多处用 **AST 钉死** `save_template` / `delete_template` 的函数体（判据落在"这个函数里必须有什么"，不是"这个字符串在不在"）。文件路径一变，这些**全部误报红**。
3. **单测打桩打在模块对象上**：`tests/test_routes.py` 用 `mock.patch.object(routes, ...)`。搬走之后，`routes.<name>` 是否仍是同一个对象，取决于导出方式。

## 三、三步方案

### 第 1 步 · 抽公共模块（`src/server/common.py`）

把**与业务无关、被多处使用**的助手搬过去，`routes.py` 改为从它导入：

| 候选 | 现位置（约） | 用途 |
|---|---|---|
| `_fail` | `routes.py` 前段 | 统一失败响应（`{ok, code, message, detail}`） |
| `_tmp_sibling` | 83 行附近 | 原子写的唯一临时名（V0.0.30 A-P3-2） |
| `_env_truthy` | 955 行附近 | 环境开关解析 |
| 其他纯工具（如有） | 视实际情况 | — |

**验收**：`routes.py` 只减不增行为；四件套全绿。此步**不动任何业务函数**。

### 第 2 步 · 搬「模板族 CRUD」→ `src/server/templates.py`

**范围**（按当前行号，约 **355–862 行**，≈508 行）：

```
_template_source / _strip_template_ext / _read_template_doc
list_templates / load_template / export_template
save_template / _template_path_or_raise / _template_trash_dir
delete_template / rename_template / import_template
```

**搬完后 `routes.py` 预计 → 约 39,000 B**（余量回到 ~26 K）。
**若后续还要更大余量**，第二步可扩到把「模板目录绑定」（864–1162）一并搬入 `templates_dir.py` → `routes.py` 约 27 K。

**导出方式**：`routes.py` 用 **显式 `from .templates import (…名字…)`**（**不要 `import *`**）——
显式导入让"谁被搬走了"在 `routes.py` 里**一眼可数**，也让 `mock.patch.object(routes, name)` 继续有效。

**⚠ 搬迁纪律**：函数体**逐字节照搬**、不顺手改逻辑。搬完用
`git diff -M --stat` 应显示为 **rename/移动**而非重写；对每个函数做一次「新旧源码逐字节比对」脚本（只允许缩进变化）。

## 四、验收标准（缺一不可）

1. **四件套全绿**：`verify` / `unittest` / `smoke` / `browser_smoke`（当前基线 **113/0 · 499 OK · 35/0 · 33/0**）
2. **`store.py` 指纹**：搬完 `commit` 后，**`digest` 必须与搬前一致**（纯搬迁不改内容）——
   若 `digest` 变了，说明**改了行为或改了文件集**，停下来查
3. **`verify --against`** 与搬前基线一致
4. **反向验证**：至少 3 例注入证明"搬走后守卫仍能抓住原缺陷"（不是空跑）
5. **体积实测**：`routes.py` 与 `src/` 两条线都要复算，并**写进文档**

## 五、风险与回退

| 风险 | 说明 | 应对 |
|---|---|---|
| 搬错一行 | 模板 CRUD 有原子写 / 回收站 / 覆盖确认逻辑，错一处很隐蔽 | 逐函数新旧**逐字节比对**；`store` 指纹不变是硬判据 |
| 守卫假红 | AST 锚点换文件后可能报"函数缺失" | 先改锚点再跑，**不允许**为了变绿而删锚点 |
| 总量线更紧 | 拆模块**省单文件线、吃总量线**（V0.0.49 记录：搬迁挤出 18,866 B，骨架净吃回 2,690 B） | 先算 35.8 K 余量够不够；不够就先不拆 |
