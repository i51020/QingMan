#### 21:26 · 裁定登记：favicon 简化版 **现在不做**（纯文档，不升版）

**依据**：用户采纳上一轮专业建议 —— favicon / 小尺寸简化标记**暂不做**（对应 `docs/项目约定.md` §P2 第 9 项由「待裁定」结案）。

**决策依据**（均来自 V0.0.3 的尺寸实测，非推断）：

| 尺寸 | 实测表现 |
|---|---|
| 16px | **轮廓成立** —— 外环 + 中心点仍可辨认；藤蔓尖端细节丢失（未到「糊成一团」） |
| 20–24px | 清晰，细节开始可辨 |
| 32px 以上 | 完全清晰 |

**三条理由**：① favicon 的职责是「可识别」而非「看清细节」，16px 下仍是一眼能认出的环形符号；② 简化版意味着**第二套需同步维护的图形**，源文件一改（如调整藤蔓走向）两套即漂移，收益小、长期成本高；③ 真正需要简化版的场景是 **16px 功能性图标**（工具栏按钮、列表项前缀），当前无此需求（顶栏为 22px）。

**已登记的坑（将来做 favicon 前必读）**：favicon 若直接用 `assets/logo.svg`，其 `currentColor` 在独立文档中会解析为**黑色**，深色浏览器标签栏下不可见。故届时须**单独定颜色策略** —— 固定中性色（如品牌绿 `#2f8f6b`，深浅标签栏均可辨）或另出一份带 `@media (prefers-color-scheme)` 的文件。此决策应与「是否加 `<link rel="icon">`」一并定。

**重议触发条件**：出现 16px 级功能性图标需求时，或确定要加站点 favicon 时。

## 维护规则

1. **只追加**：新进度一律在「时间线（倒序）」顶部插入新条目，历史条目不改写（除非更正事实性错误，须在条目内标注【更正】）。
2. **每条必备五要素**：`时间` + `发生了什么` + `涉及版本` + `产物` + `验证`。
3. **时间取实测值**：优先用文件 mtime、工具返回、对话时间戳；无法确定时标注【约】或【推断】。**禁止凭感觉写时间**。
4. **版本号为参考标签**：版本号只作索引，允许跳号、合并、同一版本内多次推进。判断进度看本文件最新条目，不看版本号大小。
5. **版本索引自动派生**：`versions/*/MANIFEST.json` 与 `MANIFEST-r<N>.json` 是版本索引的唯一数据源（`python tools/store.py log`）。手工索引表与工具输出不符时，**以工具为准**。
6. **条目粒度**：一次「实质性工作」记一条；纯只读核实、简单问答不记。
7. **版本号与时间线的关系**：版本号 = 里程碑标签（仅在「交付了可回退的完整状态」时递增）；时间线 = 过程记录。两者非一一对应。
