## 二、F · 多选批量操作

### 2.1 需求解读【推断】

树区支持**多选**，对选中集合执行**批量操作**。

### 2.2 多选交互【推断】

| 手势 | 行为 | 备注 |
|---|---|---|
| `Ctrl`/`Cmd` + 单击 | 切换该节点选中态（离散多选） | 业界标准 |
| `Shift` + 单击 | 范围选择（从锚点节点到当前节点，取**可视序**） | 锚点 = 最后一次无修饰单击的节点 |
| 单击（无修饰） | 清空多选，回到单选 | |
| `Esc` | 清空多选，回到单选（不改变主选中） | |
| `Ctrl` + `A` | 全选**根之下**全部节点 | 根节点**永不可选**（不可删/不可移） |

### 2.3 批量操作清单【推断 · 请重点批注】

| # | 操作 | 价值 | 风险 | 我的建议 |
|---|---|---|---|---|
| 1 | **批量删除** | 高 | **高**（破坏性） | **做**，必须带确认弹层（列数量 + 不可撤销提示） |
| 2 | **批量移动** | 高 | 中 | **做**，与现有拖拽衔接（拖动多选集合） |
| 3 | **批量复制路径 / 清单** | 中 | 零（只读） | **做**，复用 `inspector.copyText` |
| 4 | **批量重命名** | 高 | 中 | **暂缓**——需「规则 UI」（前缀/后缀/查找替换），是三项里最重的一块 |
| 5 | 批量展开 / 折叠 | 低 | 零 | **不做**——`展开全部` / `折叠全部` 已覆盖，批量语义无增量 |

### 2.4 必须提前定义的边界（**专业设计的关键**）

1. **父子同选去重**：若同时选中父与子，删除/移动时**只作用于最外层祖先**（否则重复操作 + 统计错）。
2. **拖拽语义**：拖动一个「已在多选集合内」的节点 → 移动**整个集合**；拖动「不在集合内」的节点 → 只移动该节点（业界标准）。
3. **右键菜单语义**：右键节点若**在**多选集合内 → 菜单作用于**整个集合**（文案显示「删除选中 N 项」）；若**不在** → 作用于**该节点**并清空多选。
4. **根节点**：永不可选（连带不可批量删除/移动）。
5. **多选态与检视器**：见 §五.1（须与 H 联合定义）。

### 2.5 数据与契约影响【已核实】

| 面 | 影响 | 说明 |
|---|---|---|
| `store` 契约 | **需扩展** | `selectedId: string` → 保留为主选中（锚点），**新增派生** `selectedIds: string[]`。保留 `selectedId` 可让 `tree-view` / `inspector` / 键盘操作的现有调用点**无需改动** |
| **`editor.json` 契约** | ✅ **零影响（已核实）** | `schema.json` 的 `editorDocument` 只含 `schemaVersion` / `savedAt` / `root` **三键，无选中态**；`main.js` 保存 payload 亦仅送 `root: toDocumentNode(store.get().root)`（L411）。→ **多选态纯内存，不落盘、不入契约** —— F 的**主要契约风险消除** |
| undo / redo | **天然兼容** | 快照式（整树）；批量操作**只推一次快照**，整体可撤销 |
| 自动保存 | ✅ **无影响** | 多选态不入盘（同上），`markDirty()` 的写盘内容不含选中态 |
| 守卫 | 需同步 | `browser_smoke` 增多选断言；`REQUIRED_IDS` 视新增 DOM id 而定 |

### 2.6 风险

- **最高**：批量删除不可撤销的误操作 → 确认弹层为**强制**。
- 多选 + 拖拽 + 右键三套交互叠加，**状态机复杂**（这是 F 的主要成本所在，非 UI 本身）。
- 与 `Shift` 范围选择的「可视序」定义：折叠的子树是否计入范围？（建议：**只计当前可见行**，语义最直观）

### 2.7 体积估算【推断】

**8–14K**（选择模型扩展 + 多选渲染 + 批量菜单 + 确认弹层 + i18n 约 10 键 + CSS）

## 三、G · 工具栏三分组

### 3.1 需求解读【推断】

把工具栏按钮重组为**三个语义组**。

### 3.2 现状诊断【实测 + 判断】

现状确有 3 个 `divider`（视觉 4 段），但**语义分组错位**：

| 问题 | 说明 |
|---|---|
| ① | **撤销/重做与增改删被 `divider` 分开**——但两者同属「改树」，分错了 |
| ② | **「生成」被 `spacer` 推到最右**，不属于任何视觉组，无分组感 |
| ③ | 用户读到的是「一串按钮」，而非「三组能力」 |

### 3.3 推荐方案【推断】

| 组 | 名称 | 成员 | 语义 |
|---|---|---|---|
| 1 | **编辑** | 撤销 · 重做 · 加子节点 · 重命名 · 删除 | 改树（含历史） |
| 2 | **视图** | 展开全部 · 折叠全部 | 观察（**不改数据**） |
| 3 | **输出** | 生成 | 落盘 / 预览（保持主按钮 + 右侧） |

> 该划分的依据：**改动数据的 / 只看不改的 / 产生结果的**——三类行为在心理模型上互斥，是分组最稳的切法。

### 3.4 待定选项【请批注】

| 选项 | 说明 | 取舍 |
|---|---|---|
| 是否加**微标签**（小字「编辑 / 视图 / 输出」） | 更清晰 | 占宽，窄窗下可能折行 |
| 窄窗行为 | 前两组折入溢出菜单（复用 `#btnMore` 模式） | 增加实现量 |
| 是否把「输出」组也并入右侧 | 现已是（`spacer` 分隔） | 建议保持 |

### 3.5 影响与风险

- **零 JS 逻辑改动、零契约改动**（纯 HTML/CSS + 可选 i18n）。
- 风险：**极低**。唯一注意点是新增 CSS 类须用现有 token（避免 7c 裸色值 / 7d `.skin-` 命名）。
- 体积估算【推断】：**1–3K**

## 四、H · 检视器双模式

### 4.1 四种可能的解读【推断 · 必须由你选定】

| 方案 | 含义 | 价值 | 实现成本 |
|---|---|---|---|
| **(a) 属性 ⇄ 源码** | 属性表 ⇄ 该节点子树的 JSON（复用 `toPlainTree`） | **高**——生成前可核验、可复制；与 `#genResult` 形成互补 | 低（零新逻辑） |
| (b) 属性 ⇄ 笔记 | 把 note + 生成结果提到第二视图，属性视图更清爽 | 中 | 低 |
| (c) 详细 ⇄ 紧凑 | 同一信息的两种密度 | 低（信息量相同） | 低 |
| (d) 单节点 ⇄ 全树摘要 | 单节点属性 ⇄ 整树统计（总量 / 深度分布 / 最深路径） | 中高 | 中（`countTree` 已有，需新聚合） |

**我的推荐：(a)**。理由：复用现成函数（零新逻辑）、对「生成前核验」有真实价值、与「根名方案」同一思路（**所见即所得的可验证性**）。(d) 为次选。

### 4.2 实现要点【推断】

- 切换控件：**分段控件**（segmented）或两枚 `.icon-btn`（复用现成 `ic-*`；若用图标需**新增 1 枚** SVG mask）。
- 状态存储：✅ **已核实** —— 皮肤 / 语言 / 折叠态统一由 `src/web/js/i18n/index.js` 的**带降级读写路径**持久化（L123-137），且该文件顶部**明文约定**「复用同一条带降级的读写路径，**不要在别处直访 `window.localStorage`**」（L13）。→ H 的模式状态**必须沿用该路径**，**不得**新造存储。
- 多选时检视器行为：见 §五.1。

### 4.3 影响与风险

- **只读展示，零契约改动**。
- 风险：低。守卫注意点：分段控件的类名**不得含 `.skin-`**（触发 7d）。
- 体积估算【推断】：**6–10K**

## 五、三项的交集与冲突（**专业设计必须提前定的部分**）

### 5.1 F × H：多选时检视器显示什么？

**问题**：多选后若检视器仍显示「最后点击的那个节点」，语义混乱。

**建议**：多选（≥2）时检视器进入**聚合态**——

- 标题变为「**N 项选中**」；
- 显示：合计目录数 / 文件数、**公共父目录路径**（若跨父则显示「多个位置」）、总深度跨度；
- note 文本域**禁用**（多选无单一 note 可编）；
- 源码视图（若 H 选 (a)）显示**选中集合的合并 JSON**。

### 5.2 F × G：多选后「重命名」按钮语义

**建议**：单选 → 改名；多选 → **禁用**（因批量重命名已定为「暂缓」，见 §2.3 #4）。禁用需有 tooltip 说明原因。

### 5.3 F × 右键菜单

按 §2.4 #3 的规则：在集合内 → 作用于集合；不在 → 作用于自身并清空多选。
