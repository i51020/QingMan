## 二、项目是什么

**青蔓 QingMan** —— 纯本地离线的**目录树可视化编辑工具**。左侧模板库、中间目录树、右侧属性面板，编完点「生成」即在磁盘上建出真实目录。

| 项 | 值 |
|---|---|
| 后端 | Python 标准库 `http.server`，零第三方依赖 |
| 前端 | 原生 HTML + CSS + ES Module，零构建、零 `node_modules` |
| 通信 | HTTP + JSON，仅监听 `127.0.0.1` |
| 皮肤 | 16 款（纯 CSS 变量覆盖） |
| 语言 | 中英双语 + 可扩展语言包（放文件即生效） |
| 规模 | `src/` 62 文件 / 约 656 KB（上限 800 KB）；单文件上限 64 KB |

## 四、本轮（2026-10-21）做了什么

### 4.1 修复：在线版导出模板失败（V0.3.13 主体）

**用户报障**：`https://qingman.pages.dev` 导出功能异常。

**根因**：绑定真实模板目录后，**列表读目录、导出读 localStorage**，两条读路径不同源 ⇒ 导出恒 `404 templateNotFound`。这是 `fe94be1`「读写同源」修了**写**之后，**读**路径上漏掉的最后一处。

| 文件 | 改动 |
|---|---|
| `tools/web-demo/online-store.js` | 新增并导出 `readDirTemplateText()`（读目录原文） |
| `tools/web-demo/demo-backend.js` | 新增 `readTemplateSource()` / `exportTemplate()`：**目录优先、浏览器内兜底**；`?format=` 双向转换补齐 |
| `tests/test_demo_export.py` | **新增测试文件**，8 个测试方法 / 25 条断言 |

### 4.2 修复：错误文案占位符外露（同版本内）

用户第二次反馈原话是「导出失败：**模板不存在：{name}**」——占位符原样露在界面上。**独立缺陷**。

**根因**：在线版 `fail()` 从不传 `detail`，而前端 `localizeError()` 只认 `code` + `detail` 重新成句；`t()` 对无对应值的占位符**原样保留**。

**波及 8 个错误码**：`templateNotFound` / `templateExists` / `templateNameInvalid` / `templateBadJson` / `ioError` / `tooManyNodes` / `editorBackupNotFound` / `editorBackupCorrupt`。全部调用点已补齐 `detail`。

> **教训（重要，别再踩）**：探针直接读响应 `message` 字段**复现不出这个缺陷**，因为界面走的是 `code` + `detail` 另一条渲染链。**验证必须走用户实际经过的那条路径。**

### 4.3 已部署

线上 `https://qingman.pages.dev` 已更新为 V0.3.13：
- 线上 `js/demo-backend.js` 与本地构建产物 **SHA256 逐字节一致**
- `sw.js` 缓存名自动换为 `qm-static-V0.3.13`
- 用**线上真实文件**跑导出验证 **9/9 通过**（含 `模板不存在：根本没有.json` 占位符已填充）

### 4.4 用户侧问题（已解决，非代码缺陷）

用户新建的 `视频剪辑项目.md` 模板导入失败 —— 原因：**代码围栏未闭合**（` ```md ` 开了没关）。补一行 `  ``` ` 即通过。已实测确认，**不需要改代码**。

## 六、怎么跑（含本机特有坑）

### 6.1 四件套门禁

```powershell
cd 'D:\Data\deepseek-harness\default-workspace\QingMan'
$env:PYTHONIOENCODING='utf-8'; $env:PYTHONUTF8='1'   # 必须，否则 GBK 崩

py -3 -B tools/verify.py .                          # 121 项
py -3 -B -m unittest discover -s tests              # 612 用例
py -3 -B tools/smoke.py                             # 35 项
py -3 -B tools/browser_smoke.py                     # 39 项（无头 Edge）
```

> **全部需要 danger-full-access**：这些工具都用 `tempfile.mkdtemp()`（0700 目录），
> DSH 受限沙箱下写不进去，会报 `PermissionError` / `WinError 5`。
> 这不是代码问题，**是沙箱边界**，别去改代码。

### 6.2 在线版构建与部署

```powershell
py -3 -B tools/build_static_site.py --out dist/makers-live-v0313
```

**部署**（本机特有坑，两条都踩过）：

- `wrangler` **启动器不可用**：它用 `ipc` 通道 spawn 子进程 → `spawn EPERM`。
  解法：**绕过启动器直接跑 cli.js**，并加 `--no-bundle`（避开 esbuild 的服务）：
  ```powershell
  $env:CLOUDFLARE_API_TOKEN='<令牌>'
  $env:CLOUDFLARE_ACCOUNT_ID='9b8748b981bb35f5a86ae23842b50305'
  node .\.wrangler-tool\node_modules\wrangler\wrangler-dist\cli.js `
    pages deploy dist/makers-live-v0313 --project-name=qingman --branch=main `
    --commit-dirty=true --no-bundle
  ```
- **域名不变**：始终部署到同一个项目 `qingman` 的 `main` 分支，`https://qingman.pages.dev` 长期有效。
  项目 ID `4e3652bb-1e52-4703-9b6e-0cb0e1b991b9`。

### 6.3 版本与回退

```powershell
py -3 -B tools/store.py commit --note "说明"   # 建 store 快照
py -3 -B tools/manifest.py stamp               # 记构建事实（第二层清单）
py -3 -B tools/handoff.py                      # 刷 docs/接续说明.md 实况段
py -3 -B tools/store.py checkout V0.3.13       # 按清单重建
```

> **改了什么才需要 store commit**：store 只覆盖 `src/` + `start.bat` + `VERSION`。
> 本轮改的是 `tools/` `docs/` `tests/`，**不在 store 范围内 ⇒ 回退点就是 git commit**。
