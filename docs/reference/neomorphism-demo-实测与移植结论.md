## 1. 标称参数 vs 渲染实测

demo 的 CSS 是**确定值**，但渲染出来会被模糊核与相邻元素改变，两者必须分开看。

| 项 | 标称 CSS | 渲染实测 |
|---|---|---|
| 画布 | `#ececec` | `#ececec`（L=236.0，**暖度 R−B = 0**，纯中性） |
| 暗影色 | `#d1d1d1`（比底暗 27） | 最暗 `#d5d5d5`（L=213.0），**比面暗 9.7%** |
| 高光色 | `#ffffff` | 最亮 `#f7f7f7`（L=247.0），**比面亮 4.7%** |
| 卡片凸起 | `6px 6px 12px dark, -6px -6px 12px light` | 暗影可见 **+0→+16px**；高光可见 **−14→0px** |
| 凹陷（`.neo-press`） | `inset 4px 4px 8px, inset -4px -4px 8px` | 双向对称 |
| 槽（`.tab-group`） | `inset 3px 3px 6px, inset -3px -3px 6px` | 槽位移(3) **>** 块位移(2) → 块在槽里浮起 |
| 圆角 | `--radius: 20px` | 统一 20px |

**关键**：两侧扩散 **16 vs 14px**——**镜像对称**。这是本 demo 与我当前实现的根本差异。

## 2. 三招单变量实测（三栏缝隙剖面，同口径）

方法：把 demo 的三个特征逐个注入 `prototype.html` 的临时副本，每次只动一个变量，量三栏缝隙的暗影落差与高光抬升。

| 档 | 单变量 | 暗影落差 | 高光抬升 | **立体总量** | 判定 |
|---|---|---|---|---|---|
| **A** | 基线（现状 `-2/-2/6` + `3/3/9`） | 5.5% | 5.5% | **11.0%** | — |
| **M** | 暗影改**不透明纯色** `#d6d2c9` | 5.4% | 5.5% | **10.9%** | ❌ **无效** |
| **S** | 高光位移 `-2→-3`（连带模糊 6→9） | 4.6% | 5.5% | **10.1%** | ⚠ 变差 |
| **R** | 模糊收为 **1:2**（6/9 → 4/6） | **7.1%** | 5.5% | **12.6%** | ✅ **有效 +1.6** |
| **D** | 对称 `±3` + 模糊 **6/6** | **7.5%** | 5.5% | **13.0%** | ✅ **最优** |

### 三条结论

1. **❌「不透明阴影」是无效的**（5.5% → 5.4%）。原以为它是 demo 的关键（`#d1d1d1` 是固定色、不是 `rgba`），但实测证明：**暗影落在同色系面板上时，半透明与不透明视觉等价**。而且固定色**锁死皮肤切换**（换底色就错）。→ 不该学。
2. **✅「位移:模糊 = 1:2」是唯一有效的单招**（+1.6）。物理原因：模糊半径小 → 阴影能量更集中 → 峰值浓度更高 → **在窄缝里更"实"**。我原用 1:3（偏糊）。→ 该学。
3. **⚠「对称化」单独看不出收益，但合并后最优**。注意 S 档实验**混入了第二个变量**（高光模糊同时从 6 变 9），故 S 的负收益不能单独归因于"对称化"——这是本次实验设计的已知瑕疵，如实记录。

> **与上轮结论的衔接**：上轮测得 C 档（位移 9 / 模糊 26）落差 12.7%、扩散 7.3%，已接近展板（26% / 8.3%）但卡在结构限制上。本轮 D 档用**更小的参数**（3/6）拿到 13.0% ——说明**收紧比例比放大参数更划算**，且对空间的索取更少。

## 3. demo「槽 + 块」移植实测

demo 的 `.tab-group`（槽，凹陷）> `.tab-item.active`（块，凸起）与青蔓的 `#treeCanvas` > `.tree-row` **完全同构**，可零 HTML 结构改动移植。

| 档 | 选中行底色 | 行下沿落差 | 说明 |
|---|---|---|---|
| **A** | `#f8f1de` 奶油黄 | 9.1% | 现状 F′（无槽） |
| **G1** | `#edece7` 面板色（demo 原样） | 8.2% | ⚠ **丢掉识别度**，选中行与普通行几乎无差别 |
| **G2** | `#f8f1de` + 槽 | 10.2% | 保留识别度 |
| **G3** | `#f8f1de` + 槽 + 对称 1:2 | **12.3%** | 数值最优 |

槽顶壁实测：`#edece7` → **`#d6d4ce`**（落差 10.4%），槽参数 `padding:6px / radius:12px / inset 3px 3px 6px`。

### 但视觉上有一条硬约束

**槽的可见度在大面板上极低。** 原因不是参数不够，是**尺度**：

- demo 的槽尺寸约 **200 × 40px**，3px 凹陷占高度 **7.5%** —— 视觉占比大，一眼可见
- 青蔓树区 **834 × 205px**，同样 3px 凹陷占 **1.5%** —— 只剩边缘一圈，读不出来
- 且槽底 `#e8e7e5` 与面板 `#edece7` 本身只差 1.3%，靠这 1.3% + 6px 凹陷无法形成"槽"的读感

**结论**：「槽+块」适合**紧凑分段控件**（约 200px 宽以内、单行高）；照搬到**面板级大区域**会把"平铺列表"读成"框起来的输入框"，且槽本身看不见。→ **不照搬**。

## 4. 与既有三份参考的交叉对照

### 4.1 黄饱和度 · 面积律（新发现）

| 来源 | 主黄 | 饱和度 | 亮度 | 黄的用途面积 |
|---|---|---|---|---|
| 展板（照片） | `#f0d090` | **76%** | 75% | 大块面 |
| 参考图 · 第一张（照片） | `#f8d070` | **90%** | 70% | 中 |
| **本 demo（CSS）** | `#ffd073` | **100%** | 73% | **小点缀**（仅 toggle dot / slider dot / 进度弧） |
| 青蔓现实现 | `#fbd374` | **94%** | 72% | 按钮底色 |

**规律**：**面积越小，允许的饱和度越高**。demo 的黄之所以能到 100%，是因为它只用在直径 22–24px 的圆点上；展板的黄铺在大块面上，76% 才舒服。

> 这解释了上一轮"主黄该多艳"为何三份参考互相矛盾 —— 它们本来就不在同一个面积档上。

### 4.2 光影浓度其实已齐平

| | 暗影落差 | 高光抬升 |
|---|---|---|
| demo | 9.7% | 4.7% |
| 青蔓现实现 | 9.2% | **13 单位亮（强于 demo）** |

**结论**：浓度上我已追平甚至超过 demo；**真正的差距只在扩散范围**（demo 16px vs 我 6–8px），而扩散受三栏栏距（10px）硬限制 —— 这是上一轮已定位的结构问题，本轮无新增解。

### 4.3 demo 的设计逻辑（可复用的判断框架）

1. **同色系**：底与面几乎同色（demo 画布 236 / 卡片面 235），**只靠光影分层**，不靠色差
2. **双光源镜像**：左上白、右下暖灰，位移与模糊**两侧相等**
3. **凸/凹成对表达语义**：凹陷 = 容器/未选/可输入；凸起 = 内容/激活/可点
4. **accent 只做指示器**：黄只出现在 dot / 进度弧，**按钮底色是同色凸起**（不填色）
5. **大圆角 + 大留白**：20px 圆角、40px 外边距

## 5. 结论：该学什么 / 不该学什么

### ✅ 该学（有实测支撑）

| # | 手法 | 实测收益 | 落点 |
|---|---|---|---|
| 1 | **位移:模糊 = 1:2** | 立体总量 11.0% → 12.6% | `--qm-raise` / `--qm-tap` 全族 |
| 2 | **两侧镜像对称** | 合并后 13.0%（最优） | 同上 |
| 3 | **凸/凹成对表达语义** | 语义更清晰 | 输入框 / 列表槽 / 激活态 |
| 4 | **accent 只做指示器** | — | 普通按钮回归同色凸起，黄只留给主操作与状态点 |

### ❌ 不该学

| # | 手法 | 原因 |
|---|---|---|
| 1 | **不透明纯色阴影** | 实测无效（−0.1%）；且锁死皮肤切换 |
| 2 | **「槽+块」照搬到面板级** | 尺度不匹配（3px 凹陷在 205px 高区域占 1.5%，不可见） |
| 3 | **照搬数值幅度** | demo 在"单组件 + 40px 留白"环境调参，青蔓栏距仅 10px |

### ✅ 已裁决并落地（2026-10-13 深夜 · v12）

用户裁决：「对，我喜欢这个风格（`v11_demo_self.png`），帮我把皮肤按照这种设计修改。」

| # | 裁决项 | 结果 | 依据 |
|---|---|---|---|
| 1 | 中性灰 vs 暖白 | **取 demo 的中性灰** `#ececec`（暖度 0），影色同步中性化 | demo 画布实测暖度 0；暖褐影压中性灰会发「脏」 |
| 2 | 大圆角 | **`12px`（小件）/ `20px`（面板）** | demo `--radius: 20px` |
| 3 | 主黄饱和度 | **`#fdd378`（H37 S90% L73%）** —— 以 demo 为基准，按面积律降一档 | 青蔓的黄用于按钮底色，面积远大于 demo 的 22px 圆点 |

落地实测：三栏缝隙立体总量 **9.9% → 12.7%**（与 §2 预测的 D 档 13.0% 吻合）。
完整参数、对比读数与未采用项见 `neomorphism-风格规格.md` §10。

## 6. 一条必须记住的定律

> **Neomorphism 的参数按「尺度」缩放，不能按数值照搬。**
>
> - demo 的槽 3px 凹陷 → 在 40px 高的组件里占 7.5%（可见）；在 205px 高的面板里占 1.5%（不可见）
> - demo 的阴影 6px 位移 → 在 32px 组件间距里铺得开；在 10px 栏距里铺不开
> - demo 的黄 100% 饱和 → 在 22px 圆点上舒服；在大块面上刺眼
>
> **移植时先算比例，再定数值。**

## 9. v13 落地：浮层（弹窗 / 菜单 / toast）归入软皮肤（2026-10-13 深夜）

用户指令：「弹窗也采用现在的设计风格，但是同样要注意边缘。」
—— 这句里两个要求互相拉扯，本轮用 **22 个候选 / 五轮单变量实测**把它拆开了。

### 9.1 demo 的双影为什么不能直接搬到浮层上

demo 的软双影（`-6px -6px 14px #fff` + `6px 6px 14px #d1d1d1`）成立的前提是
**元素与背景同色、同处一个表面**。而浮层身后是**遮罩**（合成底色 ≈145 灰），
于是：

- 白色高光（255）叠在 145 灰上 → 必然形成一圈**比底色亮得多**的光晕
- 实测：弱白高光(α.55) 就把弹窗左缘梯度从 **84.8 打到 42.9**（+19.6 外亮晕）；
  全强度对称双影只剩 **20.0**，外亮晕 **+68.9** —— 边界彻底不可辨
- 浅画布(236)上同样如此，只是幅度小（+9~11）→ 一样削弱边缘

**改由「暗影 + 描边 + ring」承担浮层，才是这一层级的正解。**

### 9.2 demo 教给浮层的另一条：模糊 = 位移 × 2

浮层沿用了 demo 唯一被证明有效的比例律（§3），近层 `4/8`、远层 `24/48`，全部 1:2。

### 9.3 落地值（实测定档，非估计）

| 浮层 | box-shadow（除首项外为 ring） |
|---|---|
| modal | `0 4px 8px rgba(112,112,110,.58), 0 24px 48px rgba(112,112,110,.48), 0 0 0 1px rgba(88,88,86,.26)` |
| popover / ctxMenu | `0 3px 6px rgba(112,112,110,.36), 0 10px 20px rgba(112,112,110,.30), 0 0 0 1px rgba(120,120,118,.24)` |
| toast | 同 popover |
| `#scrim` | `rgba(48,46,44,.50)`（冷蓝黑 → 中性暖灰） |

### 9.4 结果

| 指标 | 改前 | v13 |
|---|---|---|
| modal 边缘跃升 | 102.7 | **99.8**（保住 97%） |
| modal 外亮晕 | −6.1 | −3.1 |
| 遮罩后底色 | 137.8（冷，B 最高） | 141.3（暖中性，R 最高） |
| popover 外暗廓 | −30.1 | −20.9 |
| popover 外亮晕 | 0.0 | 0.0 |

**结论：在完全不牺牲边缘清晰度的前提下，把浮层的光影从"冷蓝黑"换成了皮肤同族的"中性暖影"。**
