### 2.2 光影结构

**双光源，方向固定为「光源在左上」**：

```
box-shadow:
  -Npx -Npx  Mpx  rgba(255,255,255,.92)   /* 左上·白高光 */
   Npx  Npx  Mpx  rgba(146,137,120,.22)   /* 右下·暖灰影 */
```

关键不是「更黑」，而是**偏移与模糊都大**（参考图卡片量级 ≈ 6–8px 偏移 / 14–18px 模糊）。
→ 这是与「锐利新拟物」的**根本分野**：后者投影模糊只有 1–3px。

### 2.3 关键约束（**实测得出的硬边界，照搬会踩坑**）

| 约束 | 实测值 | 后果 |
|---|---|---|
| 卡片面 vs 画布对比度 | **1.020 : 1** | 几乎无差别 ⇒ **完全靠光影分层** |
| 分隔线 vs 背景对比度 | ≈ 1.14 : 1 | 几乎不可见 |

> `soft_preview.html:483` 已记录同一结论：
> 「样图的『卡片面 1.04:1、分隔线 1.14:1』直接照搬会让**目录树分层消失**，hybrid 保留结构线正是为此。」

**⇒ 落地铁律：本风格**不能**在没有描边的情况下用于密集列表（目录树、模板列表）。
必须保留 1px 结构线（= 项目所谓「青蔓化 / hybrid」档），或给行高足够的留白。**

### 4.1 挂载方式

`<html lang="zh-CN" data-soft="hybrid">` + 文件末尾独立 `<style id="qmSoftSkin">`（可整块摘除）。
**不直接改 `base.css` / 皮肤文件**：`base.css` 与仓库逐字节同源（sha256 已校验），
改它会破坏同源声明；全部差异隔离在一个 `<style>` 块内。

### 4.2 三条硬化规则（实测教训，非审美偏好）

| # | 规则 | 来源 |
|---|---|---|
| ① | **有底才有影** —— 透明底元素配 `box-shadow` 会投出**方形影框** | v8 把 `.ob-gen` 改透明底却留阴影 = 「把删掉的边框换成影子做的框」 |
| ② | **父子不能都浮起** —— 父层浅底柔光 + 子按钮再浮起 = 叠成一圈白晕 | v9 前「一键生成」放大后「黄块贴白块」的成因（用户截图 #1） |
| ③ | **小控件光影必须比区块短** —— 偏移 2–4px、模糊 5–10px | 参考图能出柔光是因为卡片面积大；34px 按钮照搬 17px 偏移只会糊 |

### 7.2 展板实测（Pillow 采样）

| 项 | 实测值 |
|---|---|
| 画布 | `#efece7`（暖度 R−B = 8） |
| 卡片面 | `#ede8e2`（暖度 11） |
| 卡片面/画布亮度差 | **1.3%** → 「同色系」成立 |
| 大卡阴影扩散 | **8.3%**（60px ÷ 719px 卡宽） |
| 大卡阴影落差 | **26%**（紧贴边缘） |
| 阴影暖度 | 22（卡面 8–11）→ **阴影比卡面更暖** |
| 主黄高频色 | `#f0d090` → H40 **S76%** L75% |
| 暖黄占比 | **5.27%**（印证「点缀」） |

### 7.3 与本实现的差距（同口径实测）

| 指标 | 展板 | 当前实现 | 判定 |
|---|---|---|---|
| 大件阴影扩散 | 8.3% | 3.3% | 偏窄 |
| 大件阴影落差 | 26% | 9.2% | 偏弱 |
| 主黄饱和度 | 76% | 94% | 偏艳 |
| 画布暖度 | 8 | 3 | 偏冷 |

**核心结论：「柔」≠「弱」。** 展板是「大扩散 + 中等浓度」= 柔而实；当前是「小扩散 + 低不透明度」= 弱而不柔。

**结构性天花板**：三栏紧拼接（栏距 10px），相邻面板的白色高光（lum 249）与本面板暗影（lum 213）
落在同一区间互相抵消 → 纯调参数无法达到展板落差，需减掉相邻一侧白光或大幅拉开栏距（属结构改动）。

> 三档对照实测（`shots_v6/v10_tier_ABC.png`）：A 现状 9.2%/3.3% ｜ B 温和 9.6%/6.9% ｜ C 展板档 12.7%/7.3%。
> 扩散已达展板水平，落差仍受上述结构限制。**建议取 B 档**。

## 11. 第五次落地：弹窗 / 浮层统一为软皮肤（2026-10-13 深夜 · v13）

### 11.1 这句话里藏着一对互斥要求（必须先讲清）

「采用现在的设计风格」= Neomorphism 软双影（白高光 + 暗影）；
「注意边缘」= 边界必须可辨。
—— 而**白色高光天然把边界糊成一圈光**。这不是审美偏好之争，是可测量的物理结果（见 11.2）。

### 11.2 五轮单变量实测（22 个候选 · 逐设备像素剖面）

方法：无头 Edge `dsf=2` → 补偿窗口 → 探针取 rect → 截图 → **自「全行梯度最大点」定位物理边缘**
（不依赖跨进程 rect，失败过一次已有记录）→ 沿线扫亮度剖面。
指标：**边缘跃升**（跨过边界时的亮度跳变 = 锐度）、**外亮晕**（外侧比背景亮多少）、
**下影**（下侧最深值比背景暗多少 = 立体感）。

| 轮次 | 变量 | 关键读数 |
|---|---|---|
| 1 | 弹窗影 5 档（含完整双影） | v12 的中性影 `rgba(140,140,138)` 落在遮罩底(≈145)上，**立体感只剩 4.1**；现状冷蓝黑影 33.7 |
| 2 | 影色 × 遮罩色 6 档 | 弱白高光(α.55) → 边缘跃升 84.8 → **42.9**；完整对称双影 → **20.0** 且外亮晕 **+68.9** |
| 3 | popover 4 档 | 浅画布(236)上白高光同样造 +9~11 外亮晕 → **一样削弱边缘**，只是幅度小 |
| 4 | popover 终值 3 档 | Q2 定档：外暗廓 −20.9 / 外亮晕 0.0 / 下影 72.1 / 跃升 +33.9 |
| 5 | 立体力度 × 遮罩深度 4 档 | **加深遮罩**比加粗阴影更划算：底色 157→139 时，跃升 84.8 → **99.8** |

### 11.3 三条可复用的物理律（本轮新增，建议并入 §6 复查清单）

1. **影色必须比「所在底色」暗** —— 是"所在底色"，不是"画布色"。浮层在遮罩上时底色是
   "画布 × 遮罩"的合成色；皮肤的中性影 140 在合成底 145 上直接失效（立体感 4.1）。
2. **白高光只属于「内嵌元素」** —— 按钮 / 卡片 / 输入框与背景同色，靠光影凸起；
   浮层与背景是**材质分离**关系，靠"暗影 + 描边"区分。把双影硬套到浮层上 = 毁边（跃升 20.0）。
3. **边缘锐度 ≈ 面板面与底色的亮度对比** —— 想更清晰，优先"压深遮罩"而不是"加粗投影"；
   加粗投影只会扩大光晕、弄脏画面。

## 12. 第六轮：皮肤选择器修复 + 并入主线（2026-10-14 凌晨 · v14）

**用户指令**（原话）：「修复：皮肤选择器切了没反应（15 款呈现同一套）／再检查一遍皮肤
还存在什么问题，如果没有问题了就并入主线」

### 12.1 根因（一句话）

软层 `html[data-soft]` 的特异性 **(0,1,1)** 高于皮肤文件的 `:root` **(0,1,0)**，
而 v12 的软层里**重定义了 16 个配色变量**（`--qm-bg` / `--qm-surface` / `--qm-accent` …），
于是 15 款皮肤的颜色被整层压死 —— **切换动作成功，配色纹丝不动**。

实测（修复前）：15 款皮肤的 `link.href` 都正确切到了各自文件，
但读到的 `--qm-bg` **全部是 `#ececec`**（软层值），像素级完全相同 `(240,240,238)`
⇒ **唯一渲染组合数 = 1**。

### 12.2 修复原则

**软层从「配色层」降级为「光影语法层」**：
- 配色 → 全部交回 `tokens.css` 的 `:root` 与 15 款皮肤；
- 光影「颜色」→ 引用皮肤自带的 `--qm-shadow-light` / `--qm-shadow-dark`。

为什么影色必须引用皮肤（而不是自拟中性灰）—— 实测两档皮肤给出的值方向相反：

| 皮肤 | `--qm-shadow-dark` | `--qm-shadow-light` |
|---|---|---|
| 浅色 s06 / s11 | 灰 α.15 | 白 α.55 |
| 深色 s03 / s07 / s14 | 黑 α.62 | 白 α.06 |

写死成 `rgba(140,140,138)` 时，深色皮肤上灰影**比底色还亮** → 光影方向整体反转。

### 12.3 改动了哪几处

| 位置 | 改前 | 改后 |
|---|---|---|
| 变量层 | 16 个配色变量 + 硬编码影色 | 全删；影色 → 皮肤变量 |
| `.btn.btn-primary` | 黄色渐变 `#ffe19b → #f9cb63` | `var(--qm-btn-bg)` / `-hi`（各皮肤主色） |
| 选中态描边（`.tpl-row` / `.tree-row`） | `rgba(240,222,175,.92)` | `var(--qm-accent)` |
| 面板内高光 | `rgba(255,255,255,.90)` | `var(--qm-edge-hi)` |
| 浮层影（modal / popover / toast） | `rgba(112,112,110,…)` | `var(--qm-shadow-dark)` **叠层**（3 / 2 层） |
| `#scrim` | `rgba(48,46,44,.50)` 暖灰 | `rgba(0,0,0,.50)` 纯黑 |

**遮罩为何改纯黑**（实测）：深色皮肤 s12（bg `#1a1a1a`）下，暖灰遮罩把背景压到 L≈44，
而弹窗面 `--qm-surface = #282828` 只有 L≈40 —— **弹窗比背景还暗，边界消失**。
改纯黑后：浅色皮肤弹窗/背景落差 98 → **131**；深色皮肤 −4 → **+27**（由反转转正向）。
