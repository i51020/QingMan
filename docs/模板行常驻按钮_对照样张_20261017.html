更正 1：.tpl-more 从未在 JS 里存在过

实测 git log --all --oneline -S "tpl-more" -- src/web/js/ ⇒ 0 命中。 它首次出现在 CSS 是 0a233ba（V0.0.40 · UI 定版），属先写了样式、却始终没装标记。 ⇒ 我方 soft.css 里 12 处提及 .tpl-more （其中剔注释后仍剩 8 行真规则 / 守卫）是 幽灵 · 死码 （src/web/js 与 *.html 命中 0 ⇒ 无任何 DOM 消费者）。

更正 2：soft.css 的注释与史实不符

soft.css:44 原文写「.tpl-more —— ⋮ 按钮已于 V0.0.38 随「右键菜单改造」移除」。 但 V0.0.38 移除的是 .tpl-ops（git show 394be81^:src/web/js/main.js 可见 tpl-ops + 2 颗 .tpl-op 文字按钮）。
⇒ 准确表述应是：⋮ 不是被移除的，而是从未被装上；被移除的是 2 颗常驻文字按钮。 这条注释若不改，将来又是一条「读起来像史实」的错误记录（同《错误笔记》§三.85 家族）。

更正 3：设计稿自己写了这不是二选一

prototype.html:2185
/* 行尾 ⋮：打开**既有** #ctxMenu（复用 V0.0.38 的右键菜单与定位夹取，不另造一套） */

⇒ ⋮ 是菜单的可见入口，不是菜单的替代品。两项主张在「动作只有一套来源」上方向一致： V0.0.38 要的是「行内不再挂一排操作按钮」，设计稿要的是「入口能被看见」—— 一颗 ⋮ 同时满足两者，且不新增第二个动作来源。所谓「直接冲突、各有理由」，是把 「删除文字按钮」误读成「删除一切行尾元素」的结果。

⑥ 连带面与代价

面结论
图标册（守卫 7aj） 零影响。⋮ 用 .ic-more —— 已在图标册 21 枚内， 且顶栏 #btnMore 已在用 ⇒ 7aj① 的「定义↔使用双向配对」不受影响，不动图标册。

⑦ 结论与建议

1. 这是「伪两难」。设计稿自己的实现注释写明「复用既有 #ctxMenu，不另造一套」， 与 V0.0.38「操作收进菜单」同向。真正被否掉的只是「行内挂一排常驻操作按钮」， 不是「行尾有一个入口」。（见 §② 更正 2 / 更正 3）

2. 建议走「丙」（⋮ 复用同一菜单）。四路中它唯一同时做到： 可发现性↑、动作来源仍唯一、顺手点亮 8 处既有死码、零新增色值。

3. 丙-1 与丙-2 之间，我倾向丙-2（设计稿原样），三点理由（主观建议，请裁决）：

  • 本样张实测 丙-1 的 27×27 比丙-2 的 22×22 更占位（后者在 49.6 px 行高里更「轻」）；
  • 丙-2 是真圆形 999px（实测圆角 999px）， 与「图标按钮族」的圆角方块在语感上区分开 —— 更像「入口」而非「按钮」；
  • 丙-2 补上了「选中行点亮」（实测 opacity 1 vs 丙-1 的 0.45）—— 正在操作的那一行，入口不该还是半透明。

代价：丙-2 要对齐 3 条外观规则（尺寸 / 圆形 / 取色），丙-1 可 0 行 CSS。

4. 无论选哪条，建议同批清掉「名不副实」：soft.css:44 那条「⋮ 已于 V0.0.38 移除」的注释 必须改成如实表述。否则它会继续充当一条「读起来像史实」的假记录。

5. 若选「甲」（维持现状），那也应明确记为设计取舍而不是继续挂「待议」， 并把 soft.css 里那 12 处提及（8 行真规则 ＋ 注释）一并清掉 —— 让「没有入口」是一个决定，而不是一句悬着的注释。
