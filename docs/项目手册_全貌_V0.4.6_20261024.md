## 一、一页速览

**青蔓 QingMan** 是一个**目录树设计器**：在浏览器里可视化编辑一棵目录树，然后一键在真实磁盘上
生成对应的文件夹与文件。它解决的是「建项目骨架」这件事 —— 手工在资源管理器里一层层点太慢，
而骨架本身又是可复用的知识。

| 项 | 值 |
|---|---|
| 中文名 / 英文名 | 青蔓 / QingMan |
| 当前版本 | **V0.4.6** |
| 形态 | ① **本机版**（Windows，双击 `start.bat`，Python 本地服务）<br>② **在线版**（纯静态站点，浏览器里跑一个同契约的「演示后端」） |
| 运行要求 | Windows 10/11；本机版需 Python 3.8+（便携包已内置运行时，无需另装） |
| 网络 | **完全离线**。本机服务只监听 `127.0.0.1`，不对外、不上报 |
| 唯一外部依赖 | 无。前端为原生 HTML/CSS/ES Module，无框架、无 CDN、无第三方 JS 包 |
| 许可证 | **MIT** |

### 「不是什么」

- **不是**云端应用：本机版没有任何服务端账号体系，数据在你自己磁盘上。
- **不是**通用文件管理器：它只做「按树生成」，**不删除**、不覆盖已存在的文件。
- **在线版不是本机版的等价物**：浏览器拿不到任意路径，只能由用户点选文件夹；桌面快捷方式、
  本地服务、真正的路径输入只有本机版有。

## 二、快速开始

### 2.1 在线试用（零安装）

打开 **<https://i51020.github.io/QingMan/>**（GitHub Pages，V0.4.6）。
需要 Edge / Chrome（写盘依赖 File System Access API）。

### 2.2 本机版 · 便携包（推荐给最终用户）

1. 到 **<https://github.com/i51020/QingMan/releases/latest>** 下载 `QingMan-V0.4.6-portable.zip`（约 17.5 MB）；
2. 解压到任意目录（例如 `D:\QingMan\`）；
3. 双击 **`start.bat`**。

脚本会自动：定位 `src/` → 优先用随包 `runtime\python.exe`（其次 `py -3`、`python`）→
在 **8765–8775** 之间挑一个空闲端口 → 起服务 → 打开浏览器。

> 提取码/杀软提示：便携包未签名，Windows SmartScreen 可能提示「未知发布者」，选择「仍要运行」。

### 2.3 源码运行（开发者）

```bat
git clone https://github.com/i51020/QingMan.git
cd QingMan
start.bat
```

或手动：

```bash
cd src
python -m server
```

### 2.4 第一次使用（三次点击）

1. 左栏点一套模板 → 载入目录树（可 `Ctrl+Z` 撤销）；
2. 中栏「根名」填你要生成的根文件夹名；
3. 中栏「目标位置」选一个已存在的文件夹 → 点 **一键生成**。

先点「演练」可只预览将创建哪些目录/文件，不碰磁盘。

## 四、架构总览

```
浏览器
├─ src/web/index.html · help.html · support.html      三个页面（原生 HTML）
├─ src/web/css/  tokens · base · layout · soft · skins/  设计变量 + 皮肤
└─ src/web/js/
   ├─ main.js                装配入口（唯一启动点）
   ├─ core/                  api（唯一网络出口）· store（文档状态）· bus（事件）· errors（错误本地化）
   ├─ modules/               tree-model（模型）· tree-view（视图）· templates（模板库）· selection · tpl-order
   ├─ ui/                    ctx-menu · inspector · layer · toast · tooltip · skin-picker · lang-picker · backups · launch-icon · help-doc
   └─ i18n/                  取词运行时（词典在项目根 locales/）

本机服务（Python 标准库 http.server，无第三方包）
├─ app.py          路由分发、静态文件、安全响应头
├─ routes.py       编辑态 / 生成 / 快捷方式 / 图标 / 打开目录
├─ templates.py    模板 CRUD、目录绑定判据、导入导出
├─ backups.py      历史版本枚举与恢复
├─ dtree_core.py   纯逻辑：校验、解析/渲染 .md、写盘
├─ config.py       路径与限额解析（数据目录 / 模板目录 / 环境变量）
└─ common.py       原子写的唯一临时名助手

共享契约
└─ src/shared/schema.json · error-codes.json          接口与错误码的唯一真源
```

### 4.1 关键设计取舍

| 取舍 | 为什么 |
|---|---|
| **Python 标准库，零第三方依赖** | 用户双击即用，不需要 `pip install`；也让便携包体积可控 |
| **前端零框架、ES Module** | 离线可用、无构建步骤；`src/` 就是最终产物（只做拷贝与注入） |
| **`api.js` 是唯一网络出口** | 所有请求/错误归一化只有一处，错误本地化与守卫都锚在这里 |
| **只复制不删除** | 删模板/删备份都是「移入 `.trash/`」，可人工找回 |
| **模板 `.md` 与 `.json` 双格式** | `.json` 给程序，`.md` 给人读、可进版本库；两者由工具保证**逐节点等价** |
| **契约下沉到 `schema.json`** | 前后端/在线版三方共用一份形状定义，避免各写一遍 |

## 五、数据与契约

### 5.1 编辑态文档（`editorDocument`）

```json
{
  "schemaVersion": 1,
  "savedAt": "2026-10-24T13:00:00",
  "root": {
    "id": "n1",
    "type": "dir",
    "name": "我的项目",
    "note": "可选，纯文本",
    "children": [
      { "id": "n2", "type": "file", "name": "说明.md", "content": "" }
    ]
  }
}
```

- `type` 只有 `dir` / `file`；文件用 `content` 存正文，目录用 `children`。
- **`id` 全树唯一**，由前端 `reserveIds()` 发放；重名在同层**不允许**（大小写不敏感）。
- 根节点 `name` 可以为空 —— 空名表示「生成时不建根文件夹」（方案 C：根名即树根）。
- 老文档缺字段一律按默认值读，**不做迁移**。

### 5.2 模板格式

模板是**嵌套字典**（目录=对象、文件=内容字符串），与编辑态文档**不同构**，由
`fromNestedTree()` / `treePayload()` 互转。

```json
{ "schemaVersion": 1, "name": "项目模板", "description": "一句话说明", "tree": { "素材": {}, "说明.md": "# ..." } }
```

`.md` 形式（人读、可 diff）：

```markdown
# 项目模板
> 一句话说明

- 素材/
- 说明.md
  ```
  正文
  ```
```

> 文法细节与「围栏自适应」规则见 `src/server/dtree_core.py` 的 `render_md_template` / `parse_md_template`；
> 在线版用 `tools/web-demo/md-template.js` 做**逐字对应**的移植，两边改必须同步。

### 5.3 错误响应

所有失败一律：

```json
{ "ok": false, "code": "templateNotFound", "message": "中文整句", "detail": { "name": "x.json" } }
```

- **`code` 才是稳定标识**；前端用 `err.<code>` 本地化重渲染，`detail` 是占位符字典。
- 缺 `detail` 会让界面露出字面量 `{name}` —— 这是 V0.3.13 修过的真实缺陷，现有守卫盯着。
- 错误码清单在 `src/shared/error-codes.json`，**新增码必须三处齐备**（后端 / 错误码表 / 两语言包）。

## 六、HTTP 接口一览

本机服务只绑定 `127.0.0.1`，接口无鉴权（本机信任模型，见第十一节），写操作要求
自定义头 `X-QingMan: 1`。

| 方法 | 路径 | 作用 |
|---|---|---|
| GET | `/api/health` | 健康检查；返回版本、数据目录、OS 语言等 |
| GET / PUT | `/api/editor` | 读 / 写编辑态（PUT 前会轮转备份） |
| GET | `/api/editor-backups` | 列历史版本（新→旧） |
| POST | `/api/editor-restore` | 按 id 恢复某份历史版本（恢复前先备份当前） |
| POST | `/api/generate` | 按树生成真实目录与文件；`dryRun: true` 只回清单 |
| GET / POST | `/api/templates` | 列模板库 / 另存为模板（`overwrite` 才允许覆盖） |
| GET / POST / DELETE | `/api/templates/<name>` | 载入 / 重命名 / 删除（删除=移入 `.trash/`） |
| GET | `/api/templates-export/<name>?format=json\|md` | 导出原文或等价转换 |
| POST | `/api/templates/import` | 导入 `.json` / `.md`（全量校验后落盘） |
| GET / PUT | `/api/templates-dir` | 读当前模板目录 / 绑定新目录 |
| POST | `/api/templates-dir/pick` | 弹原生目录选择框，**只回报路径、不绑定** |
| POST | `/api/shortcut` | 在桌面写 `.lnk`（不可写则回 base64 供下载） |
| POST | `/api/launch-icon` | 上传皮肤联动图标（ICO，落 `data/qm-launch.ico`） |
| POST | `/api/open-dir` | 在资源管理器打开 `project` / `data` / `templates` |

> **在线版**把以上全部在浏览器内就地应答（`tools/web-demo/demo-backend.js` 拦截 `fetch`），
> 另加 `POST /api/templates-dir/grant`（点击手势内复授权）、`GET /api/demo-backup`、
> `POST /api/demo-import`、`POST /api/demo-clear`。

## 七、模板系统

### 7.1 三层来源

| 层 | 位置 | 说明 |
|---|---|---|
| 内置层 | `templates/`（随包只放 `P0_空白项目模板.json`） | 首次运行会播种 |
| 分发层 | `templates-pack/`（16 套 `.md` + 16 套等价 `.json` + 清单） | 用户自行导入；`tools/pack_templates.py` 可确定性重建 |
| 绑定层 | 用户点选的任意目录 | 与分发/内置互不影响 |

### 7.2 六段排序（口径唯一）

`新建 → 单导入 → 批导入 → 最近使用 → 使用次数 → 名称`。
排序口径是纯函数（`src/web/js/modules/tpl-order.js`），**可单测**；会话态存 `sessionStorage`
（刷新不跳序、关标签即归零）。

### 7.3 列表轮询

每 **2500ms** 轮询；判据是 `file | mtime | size` 的签名，**签名没变就不重建 DOM**
（避免列表跳动、hover 丢失）。页面不可见时暂停。

## 八、皮肤与国际化

### 8.1 皮肤

- 皮肤 = **变量覆盖文件**（`src/web/css/skins/s01…s15`）+ 默认基座；
- 契约：皮肤只给**配色/影色**，不写形态（形态归 `soft.css`）；
- 守卫：`swatch` ↔ CSS 逐值绑定、17 个配色面 × 16 组配对的 **WCAG AA** 对比度校验、
  背景三阶落差 ΔL\* ≤ 1.5。

### 8.2 国际化

- 词典在项目根 `locales/`（`zh-CN.js` / `en-US.js`），运行时在 `src/web/js/i18n/index.js`；
- **两包键集必须完全一致**（守卫强制）；
- 语言优先级：显式选择 → 真 OS 语言（本机版经 `/api/env.js` 同步注入）→ 浏览器语言 → `zh-CN`；
- 首屏不闪：`env.js` 是同步脚本，早于 module 执行。

## 九、质量门禁

### 9.1 四件套

```bat
py -3 tools/gate.py            :: 全量：实况段 + 四件套 + 两层清单 + 预算
py -3 tools/gate.py --quick    :: 跳过页面冒烟
```

| 环节 | 工具 | 当前结果 |
|---|---|---|
| 交付校验 | `tools/verify.py .` | **121 项 · 0 失败** |
| 单元测试 | `python -m unittest discover -s tests` | **624 OK**（20 个测试模块） |
| 端到端冒烟 | `tools/smoke.py`（真起服务 + 真 HTTP） | **35 项 · 0 失败** |
| 页面冒烟 | `tools/browser_smoke.py`（无头 Edge 驱动真实页面） | **39 项 · 0 失败** |

### 9.2 两条体积线

- `src/` 总量上限 **800 KB**（当前约 649 KB）；
- 单文件上限 **64 KB**（超了就要拆模块，`modules/templates.js`、`server/routes.py` 都是这么拆出来的）。

### 9.3 这个项目的两条工程习惯

1. **反向验证**：新增守卫/测试后，故意注入旧缺陷，确认它**精确失败**（不是「全绿就好」）。
2. **实况段**：`docs/接续说明.md` 的「实况」由 `tools/handoff.py` 生成，`verify` 会比对是否过期。

> CI（GitHub Actions）在 `windows-latest` 上跑同一套四件套，**步骤名即结论**（verify / unittest /
> smoke / browser_smoke / manifest 各占一个 step）。为什么不用 ubuntu：本项目只支持 Windows，
> 在 linux 上跑不出真结论。

## 十、版本与发布

### 10.1 版本号语义

**SemVer `V<MAJOR>.<MINOR>.<PATCH>`**，且**版本号只回答兼容性**：

| 变更 | 升位 |
|---|---|
| 契约破坏 | MAJOR |
| 契约兼容新增 / 新端点 / 新格式 | MINOR |
| 纯实现修复 | PATCH |
| 纯样式 / 文案 / 文档 / 工具 | **不升版**（同版本内追加修订 `@rN`） |

**构建事实不进版本号**：时间（含时区）、模型、工具链写入根 `manifest.json`（只追加）。

### 10.2 回退点（两套机制分工）

| 机制 | 覆盖 | 命令 |
|---|---|---|
| `store.py` | `src/` + `start.bat` + `VERSION` | `py -3 tools/store.py commit` ／ `checkout V0.4.6` |
| git | 全项目 | `git log --oneline` |

### 10.3 三条发布渠道

| 渠道 | 内容 | 怎么发 |
|---|---|---|
| GitHub Pages | 在线版（静态） | 推送 `main` 自动触发 `.github/workflows/pages.yml` |
| GitHub Releases | 便携包 | 网页拖附件，**资产名必须与版本严格对应** |
| Cloudflare Pages | 在线版（另一条线） | `py -3 tools/build_static_site.py --out dist/makers-live-v<版本>` → wrangler 直传 |

**发布顺序（踩过坑）**：`release.py bump` → `store.py commit` → **`git tag`** → `handoff.py` →
`gate.py` → 推 `main` 与 tag。tag 若晚于实况段生成，CI 会因「版本 tag 计数」对不上而假红。

### 10.4 产物与命名

## 十一、安全模型

**明确的威胁模型**：这是个「本机工具」，防护目标是**别的网页不能偷偷指挥你的服务**，
而不是防本机其他进程。

| 措施 | 说明 |
|---|---|
| 只绑定 `127.0.0.1` | 默认不出网卡，外部不可达 |
| Host 白名单 | 防 DNS rebinding |
| Origin 同源校验 | 跨站写请求直接拒答 |
| `X-QingMan: 1` 写防护头 | 跨站发自定义头会触发预检，而服务不响应预检 |
| 路径黑名单 | 盘根 / 系统目录子树 / 用户目录根本身 / 项目自身 |
| 文件名白名单 | 拒 `/ \ : * ? " < > |`、拒首尾空白与尾随点、拒 `..` 开头 |
| 原子写 | 先写唯一临时名再 `os.replace`，不留半截文件 |
| 安全响应头 | CSP / XFO / nosniff / no-referrer / CORP；隐藏解释器版本 |
| 只复制不删除 | 删除一律移入 `.trash/` |

**明确不防**：本机其他进程的访问、本机 DoS、用户自己导入的模板内容是否安全。

## 十二、环境变量

| 变量 | 作用 |
|---|---|
| `QM_PORT` / `QM_PORT_END` | 端口起点 / 终点（默认 8765–8775） |
| `QM_HOST` | 绑定地址（默认 `127.0.0.1`） |
| `QM_ALLOWED_HOSTS` | Host 白名单 |
| `QM_DATA_DIR` | 数据目录（优先级最高） |
| `QM_SETTINGS` | `settings.json` 路径（测试隔离用） |
| `QM_TEMPLATES_DIR` | 模板目录（优先级高于 settings） |
| `QM_MAX_NODES` / `QM_MAX_EDITOR_NODES` | 节点数上限 |
| `QM_MAX_BODY` / `QM_MAX_EDITOR_BYTES` / `QM_TEMPLATE_MAX_BYTES` / `QM_MAX_ICON_BYTES` | 各类体积上限 |
| `QM_TEMPLATE_NAME_MAX` | 模板名长度上限 |
| `QM_EDITOR_BACKUP_KEEP` | 编辑态备份保留份数（默认 5） |
| `QM_NO_GUI_PICK` / `QM_NO_GUI_OPEN` | 关断原生目录框 / 打开目录（无 GUI 环境用） |
| `QM_OPEN_BROWSER` | 是否自动开浏览器 |

## 十三、常见问题

**Q：生成时提示「目标位置不存在」？**
本机版要求目标目录**已存在**（工具不替你在任意位置建根）。在线版只能点选。

**Q：模板库列表空了？**
先看路径框下方的提示：目录被删除/改名 → 点「选择目录」重选；授权过期 → 点「重新授权」。
（V0.4.5 修过「重选同一个文件夹无效」的老问题。）

**Q：点生成没反应 / 提示浏览器不支持？**
在线版写盘依赖 File System Access API，只支持 **Edge / Chrome**，且必须是 `https` 或 `localhost`。

**Q：会不会覆盖我已有的文件？**
不会覆盖已存在文件的正文；已存在的目录/文件按「跳过」处理，并在结果清单里如实报告。

**Q：误删了模板怎么办？**
去 `templates/.trash/<时间戳>/` 找，或从 `data/.bak/` 恢复编辑态。

**Q：能改皮肤/加语言吗？**
可以。皮肤 = 在 `src/web/css/skins/` 加一个变量覆盖文件并在 `skins.js` 注册；
语言 = 在 `locales/` 加一个 `<tag>.js` 并保持键集与现有包一致（有守卫强制）。
