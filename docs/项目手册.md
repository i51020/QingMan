## 一、项目概述

青蔓 QingMan 是一个**本地离线运行的目录结构设计工具**：可视化编辑目录树，一键在磁盘上生成真实目录。

与前代参考项目（E: 盘上的文心助手接续包）的根本区别：**从零重写、按专业架构拆分**，不再使用单文件 HTML。参考项目仅作功能与内容参考，代码不继承。

## 三、技术栈

| 层    | 选型                          | 理由                    |
| ---- | --------------------------- | --------------------- |
| 前端   | 原生 HTML + CSS + ES Module   | 零构建、零依赖、离线可用，改动即生效    |
| 后端   | Python 标准库（`http.server`）   | 零第三方依赖；沿用参考项目路径，环境已具备 |
| 通信   | HTTP + JSON，仅监听 `127.0.0.1` | 本地单机，无跨域与网络暴露问题       |
| 运行环境 | Windows 10/11 + Python 3.8+ | 完全离线                  |

**实测环境（2026-10-10 用户确认）**：**Windows 11 本机**，交互仅**鼠标 + 键盘**。**触屏与其他操作系统未验证**，故不做针对性适配 —— 一切涉及触摸端 / 跨系统的改动在被明确需要且具备验证条件前不做（这是「不实证不交付」红线的直接推论）。

**分层铁律**

1. `tree-model.js` 不碰 DOM、不碰网络。
2. `tree-view.js` 只渲染、只回传事件，不改数据。
3. 所有网络请求必须走 `core/api.js`。
4. `dtree_core.py` 不 import HTTP 相关模块，可被 CLI/测试直接调用。
5. 路径与端口只在 `config.py` 定义，其余模块不得自行拼接。
6. **所有面向用户的文案只写 `js/i18n/zh-CN.js`**：除 `i18n/` 目录外，任何文件不得出现中文字符串字面量。`verify.py` 有「主界面/帮助页无硬编码中文」「JS 文案经取词表」三项把关。
7. **颜色只在 `css/tokens.css` 写死**：组件样式一律 `var(--qm-*)`；皮肤通过覆盖变量实现，组件不得出现 `.skin-*` 选择器。`verify.py` 有「组件 CSS 无裸色值」「组件 CSS 不感知皮肤」两项把关。
8. **编辑态文档的校验只在服务端定论**：前端 `fromDocumentNode()` 做容错转换，服务端 `dtree_core.validate_document()` 做严格判定。
9. **写盘目标只由 `dtree_core.check_target()` 放行**：任何落盘路径必须先过盘根/系统目录/用户目录/项目自身四类黑名单与规模阈值。
10. **新增偏好键必须声明在 `js/i18n/index.js`**（导出常量），不得把 `'qm.xxx'` 点分字面量写进别的模块（取词键闭包检查把 JS 里任何 `a.b` 字符串当作取词键）。
11. **折叠态类状态只在启动时定一次并落盘**，不要在渲染时"动态推断"（V0.0.6 实测教训）。

**帮助页/支持页与主界面的关系**：当前为**新标签打开**（规划改为应用内弹窗，见 §九.2 第 9 条）。

## 五、接口约定

| 方法     | 路径                      | 说明                                                                                         |
| ------ | ----------------------- | ------------------------------------------------------------------------------------------ |
| GET    | `/api/health`           | 返回 `{ok, app, nameZh, version}`                                                            |
| GET    | `/api/env.js`           | 首屏前置注入的偏好/环境常量（语言须在首屏渲染前定下，故不走 fetch 而作为脚本下发）                                              |
| POST   | `/api/generate`         | 生成目录（**写操作**）                                                                              |
| GET    | `/api/editor`           | 读取编辑态文档。文档损坏返回 400 `editorCorrupt`                                                         |
| PUT    | `/api/editor`           | 保存编辑态文档（**写操作，需防护头 `X-QingMan`**），服务端重新校验                                                  |
| GET    | `/api/templates`        | 列出模板库。`templates/` 缺失时返回 `available=false` + 空列表（**不报错**）；当前仅扫 `*.json`（规划扩 `*.md`，见 §十.3） |
| POST   | `/api/templates`        | 另存为模板（**写操作**）。同名默认拒写 `templateExists`；带 `overwrite:true` 时旧模板先入 `templates/.trash/` 再写    |
| POST   | `/api/templates/<name>` | 重命名模板（**写操作**）：同改文件名与文件内 `name` 字段                                                         |
| DELETE | `/api/templates/<name>` | 删除模板（**写操作**）：软删除入 `templates/.trash/<时间戳>/`，不真删                                           |
| POST   | `/api/shortcut`         | 桌面快捷方式（**写操作**），可带皮肤联动图标                                                                   |
| POST   | `/api/launch-icon`      | 上传皮肤联动图标（**写操作**），PNG-in-ICO 多尺寸校验                                                         |
| GET    | `/*`                    | 静态文件服务，根目录为 `src/web/`，带路径穿越防护                                                             |

`/api/generate` 请求体：`{ "target": "E:\\我的项目", "root": "可选根文件夹名", "dryRun": true, "tree": { "目录": {} } }`  
树结构规则：值为 `{}` 对象 → 目录；值为字符串 → 文件（字符串即文件内容）。

**写盘目标的四项前置判定**（全部服务端）：路径规范化（R1）、盘根（R2）、系统/用户/项目目录黑名单（R3–R5）、规模阈值（R6）。任一项不通过即返回 `400` + 明确错误码：`targetInvalid` / `targetTooShallow` / `targetBlocked` / `targetReserved` / `tooManyNodes`。**`dryRun` 不豁免 R6**。

**生成文件换行固定为 LF**（`newline="\n"`）：产出只由输入决定，不由平台决定。`.bat`/`.cmd`/`.ps1` 为已知例外。

**`/api/editor` 与 `/api/generate` 是两条独立的路**：前者读写编辑态（含 id），后者只读内存树并写目标目录。`treePayload()` 转成 `{名称: 内容}` 落盘载荷（不含 id），`toDocumentNode()` 转成含 id 的持久化节点 —— 两者不可混用。

## 七、版本约定与流程（核心）

**SemVer 三段式：`V<MAJOR>.<MINOR>.<PATCH>`，从 V0.0.1 起。** 版本号唯一来源是根 `VERSION` 文件。用户裁定：**当前阶段不升 minor，持续走 patch**。

| 递增      | 语义          | 例子                           |
| ------- | ----------- | ---------------------------- |
| `patch` | 修复、纠错       | V0.0.26 → V0.0.27            |
| `minor` | 新增功能 / 逻辑迭代 | V0.0.27 → V0.1.0（**当前阶段不用**） |
| `major` | 不兼容变更       | V0.1.0 → V1.0.0              |

**升版判据**：凡改动 `src/` 或交付契约 → 升版；纯文档、纯工具改动 → 不升版，只在 `docs/任务进度.md` 记时间线。

### 7.1 五步流程

| 步 | 动作     | 命令                                                     | 红线                                                                                                          |
| - | ------ | ------------------------------------------------------ | ----------------------------------------------------------------------------------------------------------- |
| 1 | 在预览区开发 | 手动                                                     | 绝不直接在 `src/` 上试错；`preview/` 按需新建，落地后即清空                                                                     |
| 2 | 交付校验   | `python tools/verify.py preview/V<版本>`                 | 82 项校验（带 `--against` 各 +2），不通过不落地；改 `src/` 另跑 `unittest` + `tools/smoke.py` + `tools/browser_smoke.py`（四件套） |
| 3 | 落地主线   | `python tools/promote.py --from preview/V<版本> --force` | 单向：预览 → 主线，只复制不删除                                                                                           |
| 4 | 提交版本   | `python tools/store.py commit --note "说明"`             | 打「此刻盘上的 `src/` + 此刻的 `VERSION`」组合，两者必须已配套                                                                   |
| 5 | 升级版本号  | `python tools/release.py bump --kind patch`            | 改主线之前必须先 commit                                                                                             |

### 7.2 存储机制：内容寻址（借鉴 Git）

```
store/objects/<sha256前2位>/<sha256>      blob 池：路径即内容的指纹，相同内容只存一份
versions/<版本>/MANIFEST.json             版本基线（修订 r1）
versions/<版本>/MANIFEST-r<N>.json        同版本后续修订（r2、r3…），不升版时留回退点
```

**修订引用语法**：`V0.0.1`／`V0.0.1@r1`／`V0.0.1@r2`。

### 7.3 版本隔离与"templates 是否进交付"的厘清

- `preview/V<版本>/` —— 试运行区，与主线物理隔离，平时只留 README.md 占位。
- `versions/<版本>/MANIFEST*.json` —— 版本清单，**只增不改**。
- `store/objects/` —— blob 池，**只增不改**。
- **纳入版本清单（store MANIFEST）的文件**：`src/` + `start.bat` + `VERSION`。`tools/` `templates/` `docs/` 为**项目级资产，不进 store MANIFEST**（即不进入"可交付版本对象池"）。
- **git 追踪范围**：全项目（含 `templates/` 18 个文件）。这与上条**不矛盾**——git 是版本控制，`store MANIFEST` 是交付隔离/回退对象池，二者口径不同。
- **用户新需求"工具不带模板"针对的是"分发文件夹内含 17 套"这一层**：运行工具时 `templates/` 仍在文件夹里。故改动是：把 17 套移出 `templates/`（进 `templates-pack/` 独立包），仅留 P0 内置（见 §十.3）。

### 7.4 回退

```bash
python tools/store.py checkout V0.0.27        # 按清单从 blob 池重建
python tools/store.py checkout V0.0.27@r1     # 精确回退到基线修订
python tools/verify.py . --against V0.0.27    # 确认与清单完全一致
```

回退时「当前有、目标版本没有」的文件，先复制进 `store/.trash/<时间戳>/` 并逐字节校验，通过后才移除原文件 —— 全程不真删。

## 八、安全说明

**三层递进的闸门**（"谁能触发" → "能写到哪" → "写多少"）：

| 层            | 约定          | 内容                                                                                                           |
| ------------ | ----------- | ------------------------------------------------------------------------------------------------------------ |
| ① 谁能触发       | §P0-5       | 仅监听 `127.0.0.1`；`app.py` 统一中间件做 Host 白名单 + Origin 严格同源 + 写操作防护头 `X-QingMan` + 拒答 CORS 预检 —— 可挡 DNS rebinding |
| ② 能写到哪       | §P0-1       | `dtree_core.check_target()`：路径 `resolve()` → 拒盘根 → 拒系统目录整棵子树 → 拒用户目录根本身（子目录放行）→ 拒项目自身及其上级                    |
| ③ 写多少 / 怎么覆盖 | §P0-1 R6–R8 | 节点总数超 `QM_MAX_NODES` 服务端直接拒绝；目录已存在 → 复用，文件已存在 → 跳过不覆盖；**全程永不删除**                                             |

**其余既有防护**

- 不收集任何用户数据、不上传任何信息
- 静态服务做路径穿越防护（`resolve()` 后校验是否仍在 `web/` 内）；模板名白名单 + `is_within` 复核
- 目录名校验：非法字符 `\ / : * ? " < > |`、控制字符、`.` `..`、Windows 系统保留名（**A-P2-2 已收紧尾随空白/点，见 §十三**）
- 请求体大小上限保护（`QM_MAX_BODY`）
- 生成操作需用户在前端主动点击


**为何边界必须在服务端**：前端弹窗与校验属 UI 层、可绕过 —— 任何本地网页（乃至经 DNS rebinding 的公网页面）都能直接 `POST /api/generate`。故 §P0-1 判定全部落在 `config.py` + `dtree_core.py`，命中黑名单返回 4xx + 明确错误码，**不是 500**。

**验收**：`tests/test_dtree_core.py`（R1–R8）+ `tests/test_routes.py` + `tools/smoke.py`。

|---|---|

3. **i18n 键闭包检查**：新增语言包时，verify 的"键闭包"会扫描任何 `a.b` 字面量，须确保新语言文件豁免或规范。
4. **数据迁移**：模板从 `templates/` 移出 + 用户目录绑定时，需考虑既有用户数据的平滑迁移。
5. **安装态可写目录**：`QM_TEMPLATES_DIR` 默认应指向用户可写目录（`%APPDATA%/QingMan/templates`），避免程序目录只读导致导入失败。
6. **模板包以 `.md` 为主**：让 Skill/Agent 生态可直接读取，工具导入时 `validate_template` 归一。
7. **根名预览原型**：`src/web/preview.html` 纯前端，零后端改动，切换 A/B/C 实时渲染"将生成的结构树"，供选型。
8. **版本策略**：用户裁定持续 patch；但导入功能 + 模板重构含新增逻辑，若后续认为属"逻辑迭代"可改 minor，以用户裁决为准。
9. **错误码闭环**：新增 `segmentTrailing`（已落盘）须确保 `error-codes.json` 与 i18n 双语文案齐备（已加 zh-CN/en-US）。
