## 一、项目概述

青蔓是一个**纯本地、纯离线**的目录结构设计工具：左侧模板库、中间目录树、右侧属性面板，编辑完点「生成」即在磁盘上得到真实目录。后端只有 Python 标准库 `http.server`，前端只有原生 HTML + CSS + ES Module，**无构建步骤、无 `node_modules`、无网络请求**。

- **不继承前代代码**：早期参考项目（E 盘上的文心助手接续包）只作功能与内容参考，本项目从零重写、按专业架构分层。
- **可交付给他人**（V0.1.0 起）：不再只管「作者本机能跑」。交付形态三条 + 一个开发交接包，见 §七.5 —— 便携发布包（含随包运行时）/ 模板包 / 接续包（读代码用）/ 完整开发包（**继续开发用，含工具与测试**）。
- **数据不污染安装目录**：数据目录四级解析（§六.2），只读安装自动落到每用户目录；旧布局**绝不搬动**。
- **不收集任何数据、不上传任何信息**，运行期零外联。

## 三、技术栈与运行环境

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | 原生 HTML + CSS + ES Module | 零构建、零依赖、离线可用，改动即生效 |
| 后端 | Python 标准库（`http.server`） | 零第三方依赖；`http.server` 足够，不引入框架 |
| 通信 | HTTP + JSON，仅 `127.0.0.1` | 本地单机；写操作另有防护头（§八） |
| 运行环境 | Windows 10/11 + Python 3.8+ | 完全离线；分布版内嵌 `runtime\python.exe` 则无需外部 Python |

**实测环境（2026-10-10 用户确认）**：Windows 11 本机，交互仅**鼠标 + 键盘**。**触屏与其他操作系统未验证**，故不做针对性适配 —— 一切涉及触摸端 / 跨系统的改动，在明确需要且具备验证条件前不做（「不实证不交付」的直接推论）。

**编码基线（《项目约定》§编码基线）**：

| 项 | 约定 |
|---|---|
| 编码 | UTF-8，**无 BOM** |
| 换行 | 源码一律 **LF**；`start.bat` 必须 **CRLF**（否则 cmd 解析异常） |
| 生成文件换行 | 固定 LF（`newline="\n"`）—— 产出只由输入决定，不由平台决定；`.bat`/`.cmd`/`.ps1` 为已知例外 |
| 解释器（门禁基线） | **`py -3`**（与 `start.bat` 同口径，本机 3.14.8）；受管 3.13.x 为备选。**报门槛数字必须附解释器 + zlib 指纹**（zip 绝对 `sha256` 跨运行时不可复现，见 §七.5） |
| `__pycache__` | 一律 `-B` 不写 —— 程序目录可能只读（Program Files / 网络盘） |
| Python 语法下限 | 3.8（不用 3.9+ 语法糖） |

### 分层铁律

1. `tree-model.js` 不碰 DOM、不碰网络。
2. `tree-view.js` 只渲染、只回传事件，不改数据。
3. 所有网络请求必须走 `core/api.js`（其余模块禁用 `fetch`）。
4. `dtree_core.py` 不 import HTTP 相关模块，可被 CLI / 测试直接调用。
5. 路径与端口只在 `config.py` 定义，其余模块不得自行拼接。
6. **面向用户的文案只写语言包**：除 `locales/` 外，任何文件不得出现中文字符串字面量（`verify` 三项把关）。**新增语言 = 放一个 `<tag>.js`**（含 `LOCALE` / `NAME` / `dict` / `helpSections`），后端枚举、前端按需 `import()`，无需改代码（守卫 7b-6）。
7. **颜色与字号只在 `tokens.css` 写死**：组件一律 `var(--qm-*)`；皮肤通过覆盖变量实现，组件不得出现 `.skin-*` 选择器。四项把关 —— **7c**（组件无裸色值）/ **7c-1**（组件无裸字号）/ **7d**（组件不感知皮肤）/ **7d-9**（皮肤顶层只许 `:root` + 变量声明），合起来才是**双向隔离**。⚠ 强制范围**已据实收窄为「色值与字号」**：间距 / 描边 / 圆角等尺寸档位**不做机器化**（2026-10-17 裁定，非「待补」）。
8. **编辑态文档的校验只在服务端定论**：前端 `fromDocumentNode()` 做容错转换，服务端 `validate_document()` 做严格判定。
9. **写盘目标只由 `dtree_core.check_target()` 放行**：任何落盘路径必须先过盘根 / 系统目录 / 用户目录 / 项目自身四类黑名单与规模阈值。
10. **新增偏好键必须声明在 `js/i18n/index.js`**（导出常量，当前 4 个：`qm.lang` / `qm.skin` / `qm.inspMode` / `qm.launchIcon`）。键名三方一致由守卫 7ai 把关；不得把 `'qm.xxx'` 字面量写进别的模块。
11. **折叠态类状态只在启动时定一次并落盘**，不要在渲染时「动态推断」。

## 五、接口约定

所有端点都在 `src/server/routes.py` / `backups.py` 中以常量定义（`XXX_PATH`），`app.py` 只做分发 —— **不要在 `app.py` 里写字面量路径**。

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | `{ok, app, nameZh, version}`；不泄露解释器版本 |
| GET | `/api/env.js` | 首屏前置注入的偏好 / 环境常量（语言须在首屏渲染前定下，故以脚本下发，不走 fetch） |
| GET | `/api/locales.js` | 语言清单（同步注入 `window.__QM_LOCALES__`，**须早于 module 脚本**） |
| POST | `/api/generate` | 生成目录（**写操作**） |
| GET | `/api/editor` | 读编辑态文档；损坏返回 400 `editorCorrupt` |
| PUT | `/api/editor` | 保存编辑态（**写操作**），服务端重新校验；落盘前先留上一版备份 |
| GET | `/api/editor-backups` | 历史版本列表（在库 `.bak/` + 归档 `.bak/.trash/<戳>/` 两类都收） |
| POST | `/api/editor-restore` | 恢复某份历史版本（**写操作**）。复用 `save_editor` ⇒ **恢复前那版先自动留档**，恢复本身也可回退 |
| GET | `/api/templates` | 列模板库。`templates/` 缺失时 `available=false` + 空列表（**不报错**）；扫 `*.json` + `*.md`，每项带 `source`（`json`/`md`）与 `mtime`/`size` |
| POST | `/api/templates` | 另存为模板（**写操作**）。同名默认拒写 `templateExists`；`overwrite:true` 时旧件先入 `templates/.trash/` |
| POST | `/api/templates/<name>` | 重命名（**写操作**）：文件名与文件内 `name` 字段同改，**按源扩展名保持格式** |
| DELETE | `/api/templates/<name>` | 删除（**写操作**）：软删除入 `templates/.trash/<时间戳>/` |
| POST | `/api/templates/import` | 导入（**写操作**）：按扩展名分派解析 → 全量校验 → **保持原格式**重序列化 |
| GET | `/api/templates-export/<name>` | 导出：**按原文件文本回传（保真，不再序列化）**；可选 `?format=json\|md` 转换格式，缺省＝原样。独立前缀，避开与 `/api/templates/<name>` 的路由顺序坑 |
| GET | `/api/templates-dir` | 读模板库目录绑定（只读，不过防护头）→ `{dir, source, available, reason}` |
| PUT | `/api/templates-dir` | 绑定模板库目录（**写操作**）：真写探测 + `settings.json` 原子写；env 遮蔽时 `applied=false` |
| POST | `/api/templates-dir/pick` | 弹**原生目录选择框**（`tkinter.filedialog.askdirectory`）；`QM_NO_GUI_PICK=1` 关断；不可用 / 取消一律**降级** |
| POST | `/api/shortcut` | 创建桌面快捷方式（**写操作**），可带皮肤联动图标 |
| POST | `/api/launch-icon` | 上传皮肤联动图标（**写操作**），PNG-in-ICO 多尺寸校验 |
| POST | `/api/open-dir` | 请求 OS 打开目录（**不落盘但会开 GUI**，与 `pick` 同等过写门槛，防跨站盲发骚扰） |
| GET | `/locales/<tag>.js` | 语言包（V0.3.0）：只认 `.js`，`resolve()` 后须仍在 `locales/` 内，无目录穿越面 |
| GET | `/*` | 静态文件服务，根为 `src/web/`，带路径穿越防护 |

**`/api/generate` 请求体**：`{ "target": "E:\\我的项目", "root": "可选根文件夹名", "dryRun": true, "tree": { "目录": {} } }`
树结构规则：值为 `{}` 对象 → 目录；值为字符串 → 文件（字符串即文件内容）。

**写盘目标的四项前置判定**（全部服务端）：路径规范化（R1）→ 盘根（R2）→ 系统 / 用户 / 项目目录黑名单（R3–R5）→ 规模阈值（R6）。任一项不通过即 `400` + 明确错误码（`targetInvalid` / `targetTooShallow` / `targetBlocked` / `targetReserved` / `tooManyNodes`）。**`dryRun` 不豁免 R6**。

**`/api/editor` 与 `/api/generate` 是两条独立的路**：前者读写编辑态（含 `id`），后者只读内存树并写目标目录。`treePayload()` 产出 `{名称: 内容}` 落盘载荷（不含 `id`），`toDocumentNode()` 产出含 `id` 的持久化节点 —— **两者不可混用**。

**错误码**：70 个，三方载体（`src/shared/error-codes.json` / 语言包两包 / 调用方），新增须三处齐备（`verify` 有专项守卫）。

## 六、运行与配置

```
start.bat            :: 自动：定位 src → 起服务 → 开浏览器
```

**`start.bat` 的解释器优先级**（V0.1.0，接收者无需自行安装 Python）：随包 `runtime\python.exe` → `py -3` → `python`。三者都不可用则明确报错并提示「重新解压完整压缩包」。**一律带 `-B`**（不写 `__pycache__`），并对「后端入口缺失 / 服务异常退出」给出可读中文错误。

### 6.1 环境变量

| 变量 | 默认 | 说明 |
|---|---|---|
| `QM_HOST` | `127.0.0.1` | 监听地址 |
| `QM_PORT` / `QM_PORT_END` | `8765` / `起始+10` | 起始端口与扫描上限 |

| `QM_NO_GUI_PICK` | 未定义（＝允许弹框） | 置 `1` 关断原生目录选择框。**自动化必置** —— 模态框不点会挂死 |

> **上限分层自洽**：`QM_MAX_BODY` 必须 ≥ 所有业务上限，否则业务错误码永远够不到。`verify` 有「请求体上限一致性」项把关。

### 6.2 数据目录四级解析（V0.1.0，分发前提）

`config.resolve_data_dir()` 按顺序取第一个成立者：

1. `QM_DATA_DIR` 显式指定 → 用它；
2. 旧布局（`<项目根>/data/editor.json` 存在）→ **沿用旧布局，绝不搬动用户数据**；
3. 项目目录可写 → 随项目走（便携形态）；
4. 否则 → `%APPDATA%/QingMan/data`（只读安装，如 Program Files）。

模板同理：`templates_dir()` 解析链为 `env > settings > 默认`；默认目录不可写时落到每用户目录，首启由 `seed_templates()` **复制**播种（只补缺失，不覆盖）。

## 七、版本、交付与门禁（核心）

### 7.1 两层结构：版本号只答兼容性

| 层 | 载体 | 回答什么 | 维护方式 |
|---|---|---|---|
| 第一层 | `VERSION` + `versions/*/MANIFEST*.json` | **兼容性** —— 契约有没有破 | 手工 / `release.py` |
| 第二层 | 根 `manifest.json` | **构建事实** —— 时间（含时区）/ 模型 / 工具链 | `tools/manifest.py stamp` |

两者通过版本号关联，各司其职。**构建事实一律不进版本号**（否则版本号变成日志）。`manifest.json` **不进 store 文件集** —— 否则每次构建都改自己，产生自指。`manifest.py check` 与守卫 7ap 同一判据源。

### 7.2 SemVer 落地（先定义「公共 API」）

**公共 API 只有三件**，其余都不算：

1. HTTP `/api/*` 的请求 / 响应契约；
2. 编辑态 `editorDocument` 结构（`schema.json`）；
3. 模板 `.md` ↔ `.json` 格式（可往返）。

**UI 视觉不属于 API** —— 改配色、改布局、改文案不构成契约变更。

| 改动性质 | 升位 | 例子 |
|---|---|---|
| 破坏契约 / 兼容新增 | **MINOR**（`0.y.z` 阶段按 SemVer §4 递增 Y） | 删字段、改语义、加必填项 → `V0.3.0` |
| 只改实现、契约不动 | **PATCH** | 修 bug、性能优化 → `V0.3.1` |
| 纯样式 / 文案 / 文档 / 工具 | **不升版** | 记 `@rN` 同版本修订 |

**`@rN` 同版本修订**：等价于 build metadata，但放在版本串外 —— 可排序、可回退、历史不覆盖。凡「同版本内第二次落地」一律走 `@rN`，不假升 patch。

> 历史背景：`V0.0.1`–`V0.0.55` 共 55 个版本 MINOR 恒为 0，实质是「改动流水号」。自 `V0.1.0` 起 MINOR 才真正启用（见《项目约定》§P0-6 M9/M10）。

### 7.3 日常流程

| 步 | 动作 | 命令 | 红线 |
|---|---|---|---|
| 1 | 在隔离区开发 | 手动 | 绝不直接在 `src/` 上试错 |
| 2 | 过门禁 | `py -3 tools/gate.py` | 四件套任一红即停，不落地 |
| 3 | 提交版本 | `python tools/store.py commit --note "说明"` | 打「此刻盘上的 `src/` + 此刻的 `VERSION`」组合，两者必须已配套 |
| 4 | 升版本号 | `python tools/release.py bump --kind patch\|minor\|major` | **改主线之前必须先 commit** |

**顺序不可颠倒**：`bump` → 同步版本戳（`schema.json` + 两语言包的 `help.versionFallback`）→ `store commit`。先 bump 后 commit 会让 `verify --against` 因旧版本戳 FAIL。

> `gate.py` 的存在理由：`handoff.py` 必须**先于** `verify` 刷新实况段，顺序靠记忆会错。它把顺序固化，并提供四个开关：`--quick`（跳过页面冒烟）、`--no-handoff`（不刷实况段）、`--budget`（体积明细）、`--doc-claims`（扫文档里与当前版本不符的「V… 实测」断言，默认关 —— 历史记录必然误报）。

### 7.4 存储机制：内容寻址

```
store/objects/<sha256前2位>/<sha256>      blob 池：路径即内容指纹，相同内容只存一份
versions/<版本>/MANIFEST.json             版本基线（修订 r1）
versions/<版本>/MANIFEST-r<N>.json        同版本后续修订（r2、r3…），不升版也留回退点
```

- **纳入版本清单的文件**：`src/` + `start.bat` + `VERSION`。`tools/` / `templates/` / `docs/` 是**项目级资产，不进交付对象池**。
- **git 追踪范围**：全项目（含 `templates-pack/`）。与上条不矛盾 —— git 是版本控制，`store` MANIFEST 是交付隔离 / 回退对象池，口径不同。

### 7.5 交付与交接产物（三种交付 + 一个开发包）

| 产物 | 命令 | 给谁 | 内容 | 特征 |
|---|---|---|---|---|
| 便携发布包 `dist/QingMan-<版本>-portable.zip` | `py -3 tools/package_release.py --runtime-dir <Python>` | **最终用户** | `src/` + `locales/` + `templates/` + `VERSION` + `start.bat` + 使用说明 + 裁剪后 `runtime/` | `--verify` 解压后**用随包运行时真启动**打 `/api/health`。`--built-at` 可注入构建时间（否则「两次构建逐字节一致」是假声明） |
| 模板包 `dist/QingMan-模板包-<版本>.zip` | `py -3 tools/pack_templates.py --zip <路径>` | **最终用户** | `templates-pack/` 16 套（`.md` 为**主分发格式**，AI/Agent 可直接读） | 确定性构建（固定时间戳 / 序 / 压缩参数）；`--check` 只校验不写盘。⚠ **zip 字节随 `zlib` 实现而变** → 清单 `zip.env` 记运行时指纹，指纹一致才比绝对 `sha256`，否则降级为自洽断言并**显式说明**（不 skip、不静默） |
| 接续包 `dist/QingMan-接续包_<版本>_<日期>.zip` | `py -3 tools/handoff_pack.py` | **接手读代码的人 / AI** | 指名白名单 11 项（`VERSION` / `start.bat` / `manifest.json` / 8 份文档）+ `src/`、`docs/`、`locales/` 三个目录 | 逐文件 `sha256`；`--verify` 自检。**`locales/` 必须显式带上** —— 漏带＝接手者拿到没有文案的程序（实测 102 → 99） |
| **完整开发包** `dist/QingMan-完整开发包_<版本>_<日期>.zip` | `py -3 tools/handoff_pack.py --full` | **接手开发并交付的人 / AI** | **整棵工作树** − `data/` `dist/` `__pycache__/` `.trash/`：即接续包全部 + `tools/` `tests/` `templates/` `templates-pack/` `store/` `versions/` `.git/` | 实测 1051 文件 / 10.9 MB（`--no-git` 省约 7 MB）。自检要求「工具 / 测试 / 版本库 / `.git` **必须有**」—— 缺任一件，`改完能验证` 或 `改坏能回退` 就静默失效 |

> **为什么必须区分「接续包」与「完整开发包」**（V0.3.0 实测）：
> 把接续包解压到空目录后 `tools/gate.py`、`tools/verify.py` 均不存在，`unittest discover -s tests` 报
> `Start directory is not importable`；`store/` `versions/` 也不在包里 ⇒ **四件套与回退全部失效**。
> 更早一步：`verify` 的必需件清单里就写着 `tools/package_release.py`，所以「只补一个 verify.py」也过不去。
> 结论：**接续包只能读、能改 `src/`，但不能验证、不能回退**；要接着开发就必须拿完整开发包。

### 7.6 回退

```bash
python tools/store.py checkout V0.3.0        # 按清单从 blob 池重建
python tools/store.py checkout V0.3.0@r1     # 精确回退到基线修订
python tools/verify.py . --against V0.3.0    # 确认与清单完全一致
```

回退时「当前有、目标版本没有」的文件，先复制进 `store/.trash/<时间戳>/` 并逐字节校验，通过后才移除原文件 —— **全程不真删**。

## 八、安全说明

### 8.1 三层递进闸门

| 层 | 依据 | 内容 |
|---|---|---|
| ① 谁能触发 | §P0-5 | 仅监听 `127.0.0.1`；Host 白名单 + Origin 严格同源 + 写操作防护头 `X-QingMan` + 拒答 CORS 预检（`do_OPTIONS` 一律 403）—— 可挡 DNS rebinding 与跨站盲发 |
| ② 能写到哪 | §P0-1 | 路径 `resolve()` → 拒盘根 → 拒系统目录整棵子树 → 拒用户目录根本身（子目录放行）→ 拒项目自身及其上级 |
| ③ 写多少 / 怎么覆盖 | §P0-1 R6–R8 | 节点总数超 `QM_MAX_NODES` 服务端直接拒绝；目录已存在 → 复用，文件已存在 → 跳过不覆盖；**全程永不删除** |

### 8.2 安全响应头（V0.2.1 审计后新增）

| 头 | 值 |
|---|---|
| `Content-Security-Policy` | `default-src 'self'; script-src 'self'; style-src 'self'; img-src 'self' data:; connect-src 'self'; object-src 'none'; base-uri 'none'; form-action 'none'; frame-ancestors 'self'`——**不给生产环境开 `unsafe-inline`**；页面探针也必须遵守（改成同源外链脚本） |
| `X-Content-Type-Options` | `nosniff` |
| `X-Frame-Options` | `SAMEORIGIN` |
| `Referrer-Policy` | `no-referrer` |
| `Cross-Origin-Resource-Policy` | `same-origin` |

`version_string()` 覆写 `Server` 头，**隐藏解释器版本**。

### 8.3 其余既有防护

- 不收集任何用户数据、不上传任何信息
- 静态服务路径穿越防护（`resolve()` 后校验仍在 `web/` 内）；模板名白名单 + `is_within` 复核；`/locales/` 只认 `.js`
- 目录名校验：非法字符 `\ / : * ? " < > |`、控制字符、`.` `..`、Windows 保留名、**首尾空白与尾随点**
- 请求体大小上限；生成需用户在前端主动点击

### 8.4 明确**不**防（写在明处，避免误解）

| 不防 | 理由 |
|---|---|
| 本机其他程序读取数据 | 纯本地工具，无认证模型；本机即信任边界 |
| 本机 DoS（超大请求 / 高频请求） | 单人本机使用，不做限流 |
| 模板内容本身的安全性 | 模板是用户数据，只做格式与规模校验，不审语义 |
| 恶意用户在本机改 `src/` | 有权改安装目录＝已拥有该机器 |

### 8.5 为何边界必须在服务端

前端弹窗与校验属 UI 层、可绕过 —— 任何本地网页（乃至经 DNS rebinding 的公网页面）都能直接 `POST /api/generate`。故判定全部落在 `config.py` + `dtree_core.py`，命中黑名单返回 4xx + 明确错误码，**不是 500**。

**验收**：`tests/test_dtree_core.py`（R1–R8）+ `tests/test_routes.py` + `tests/test_security.py` + `tools/smoke.py`。

## 九、UI 设计现状

### 9.1 现状（柔和拟物 / Soft Neumorphism）

- **风格**：`src/web/css/soft.css` 是**唯一设计语言 / 基础层**，默认生效、无属性开关。统一「语法」：光源固定左上、两侧镜像对称、模糊 = 位移 × 2。`base.css` / `layout.css` 保留结构线（1px `--qm-line`）与常态规则，视觉由软光层覆盖。
- **皮肤 = 配色档位，不是形态档位**：16 款只供配色 + 影色，形态由 `tokens.css` 的语法变量统一定义（守卫 7d-5 / 7d-7 强制）。
- **字号单一来源**：`--qm-fs-*` 9 档（`3xs` 9px … `3xl` 16px），组件不得写裸字号（守卫 7c-1）。
- **三阶落差**：`--qm-surface-2` 与 `--qm-surface` 的 **CIE L\* 落差 ≤ 1.5** 且方向随区制（浅色为负 / 深色为正）—— 填充不承担凸凹语义（凸凹归 `--qm-tap` / `--qm-tap-in` + 1px 描边）。16 款实测 **|ΔL\*| ≤ 1.37**，守卫 7d-8 常态把关。
- **布局**：左 `sidebar`（模板库）/ 中 `center`（目录树）/ 右 `inspector`（属性面板）+ 顶栏（状态 chip + 4 颗图标按钮，窄窗折入 `#btnMore`）；生成参数区**常显**（`qm.genBar` 偏好键已退场）。
- **浮层规则（V0.2.2 / V0.2.3 教训，已成判据）**：① 任何设 `display:flex` 的浮层**必须**自带 `[hidden] { display: none; }` —— 否则 `el.hidden = true` 根本关不掉（作者样式压过 UA 样式）；② 提示浮层**只在悬停 / `:focus-visible` 时显示**，`focusin` 无条件 reveal 会让弹窗一打开就自己冒提示。

### 9.3 皮肤体系：现状与新增方式

**形式**：皮肤是**纯 CSS 变量覆盖文件**，一文件一款。

```
src/web/css/skins/s16-warmgray-amber.css   ← 出厂默认
  :root { --qm-bg: …; --qm-accent: …; --qm-shadow-dark: …; … }
```

顶层只许 `:root` + 变量声明（守卫 7d-9），**不得写组件选择器**；组件 CSS 也不得出现 `.skin-*`（守卫 7d）—— 双向隔离。注册表在 `js/i18n/skins.js`：`cid` / `file` / `label`(取词键) / `swatch`(三色)。

**新增一款的四步**（当前推荐路径，零代码改动）：

1. 复制任一现有皮肤为 `sNN-<语义名>.css`，改 `--qm-*` 取值；
2. `js/i18n/skins.js` 增一条 `{cid: NN, file: 'sNN-…css', label: 'skin.NN', swatch: [底色, 面板, 强调]}`；
3. 语言包两包各加 `skin.NN` 名称键；
4. 过门禁：7d-3（swatch 逐值一致）、7d-4（WCAG 配对，款数从目录派生、自动纳入新款）、7d-8（三阶落差 ≤1.5）、7d-9（顶层只许 `:root` + 变量）。

**s01…s16 的编号不复用、不重排** —— `cid` 是持久化偏好值（`qm.skin`），重排会让老用户的皮肤跳档。

**其他可选形态**（已评估，未采纳）：① 皮肤包外置（放 `skins/` 即被发现）—— 需要后端枚举 + 注入，收益不抵复杂度；② 用户自定义配色面板 —— 会突破 WCAG 守卫，需先做约束器。二者都不在当前路线内。

### 9.4 语言包

- 位置 `locales/`（**内容资产**，不计入 `src/` 体积预算）。
- 契约：`export const LOCALE`（须与文件名一致）/ `NAME`（母语自写名）/ `dict` / `helpSections`。
- **新增一门语言 = 放一个 `<tag>.js`**，后端 `/api/locales.js` 枚举（只读文本 + 正则取 `NAME`，**不执行**语言包代码），前端按需 `import()`。当前中英各 **466 键**，键集零差异（守卫 7b-3）。
- `i18n/index.js` 内部用**相对导入**（`../../../../locales/…`）—— 绝对 `/locales/…` 只有浏览器认，Node 侧单测会 `ERR_MODULE_NOT_FOUND`。

### 9.5 帮助页 / 支持页

应用内弹窗（`#dlgHelp` / `#dlgSupport`）与独立页（`help.html` / `support.html`）**共用同一份 `helpSections`**，两处只是外壳不同 —— 改文案只改语言包，两处自动一致（曾因平行实现漂移过一次）。帮助页**不写 Markdown**（守卫 7an），也不含任何开发文档入口或链接。

### 10.3 模板系统（E / F / G 三条合并）

**目标模型**：工具**不内置业务模板**，仅保留 `P0_空白项目模板.json` 作为空案例；16 套业务模板移至独立包 `templates-pack/`，经校验后另打包分发；用户通过**目录绑定 + 实时刷新**把模板载入工具。

| 子项 | 设计 |
|---|---|
| 内置空案例 | `templates/P0_空白项目模板.json` 随工具交付，首启可种入用户模板目录 |
| 独立包 | 仓库内 `templates-pack/`（16 套 `.md` + `.json` 逐字节等价 + 说明，**不含 P0**）。`pack.manifest.json` 逐套 `name/description/dirs/files/sha256` + 整体 `digest` + zip `sha256` + `zip.env` 构建指纹 |
| 目录绑定 | 优先级 `QM_TEMPLATES_DIR > settings.json > 默认 <项目根>/templates`；落盘位置须可写（只读安装落每用户目录） |
| 实时刷新 | 前端每 **2500ms** 轮询 `GET /api/templates`；`file+mtime+size` 三元组签名不变则不碰 DOM；切后台暂停 |
| 双格式 | `.md`（AI / Agent / Skill 通用，主分发）与 `.json`（规范、承载文件内容）；白名单**按用途拆分**：`TEMPLATE_NAME`（仅 `.json`，管新建 / 改名目标）、`TEMPLATE_FILE`（双格式，管读 / 列 / 删 / 导） |
| 导出 | 按原文件文本回传（保真），可选 `?format=` 转换；与导入成环 |
| 同名处理 | 默认拒写并提示 `templateExists`；`overwrite:true` 时旧件先入 `.trash/` 再写 |

**`.md` 树语法（严格、可解析）**：首个 `# ` 行＝模板名（可选）；紧跟 `> ` 块＝描述（可选）；`- ` 行（每 2 空格一级）＝节点；名尾 `/` 或前缀 📁＝目录，否则文件；文件正文用**再缩进一级的围栏块**（正文含反引号时围栏自动加长）。`parse(render(doc)) == doc` 往返成环由测试钉住。

## 十二、犯过的错误（教训）

> 完整 99 条见 `docs/错误笔记.md`（§三 技术坑点 95 条 + 流程纪律 / 版本纪律）。此表只留**会再犯**的：

| # | 错误 | 教训 |
|---|---|---|
| 1 | 升版顺序错（先 bump 后 commit） | `verify --against` 因旧版本戳 FAIL。**bump → 同步版本戳 → commit** |
| 2 | 审计条目的「现象」未实证即据以改动 | 反向验证推翻前提：原实现已隐含保持滚动位置。**现象须先复现，再改** |
| 3 | 反向验证脚本污染换行 | `write_text` 默认把 `\n` 翻成 `\r\n`，3 个 `.py` 被整份改写。**写回源码必须显式保 LF** |
| 4 | 栈溢出用例层级取太小 | 5000 层递归版不溢栈 → 假「未复现」。**触发量级必须锚到真实上限常量（20000）** |
| 5 | 新守卫先抓到自己的错 | 锚点用了源码里不存在的 token；判据被注释里的旧写法误报。**锚在「只可能出现在代码里」的串上** |
| 6 | 「独立探针」凭 API 直觉写 | 首跑 7/18 FAIL，全是探针错（返回原因码非布尔、`depthOf` 自 0 起算）。**写探针前先读返回契约；首跑 FAIL 先怀疑断言** |
| 7 | `§` 引用指向别的文档 | 守卫只认 `docs/项目约定.md` 的编号。**指向别的文档写文件名，不写 § 编号** |
| 8 | 「套数 / 项数」照抄旧文档 | 长期写「17 套业务模板」，实际 16 套。**凡计数一律现场数一遍** |
| 9 | 绑定判据与运行态判据混用一个函数 | 默认目录在自己脚下，被判非法 → 工具一启动模板库就不可用。**判据为「场景」命名，不为「概念」命名** |
| 10 | 前缀匹配的集合路由吞掉具体路由 | `/api/templates/import` 被当成「重命名一个叫 import 的模板」。**具体路由必须先判；并给判定表达式本身加守卫** |
| 11 | 改了守卫函数的判据却没同步它的基线测试 | `browser_smoke` 的 `NORMAL` 基线与项数断言连带 22 红。**golden 基线必须与判据同步，连「条数」一起** |
| 12 | `store.py --dry-run` 只对 `checkout` 生效 | `commit --dry-run` 静默真提交。**带预演开关的工具，逐子命令确认开关真的被消费** |
| 13 | **`hidden = true` ≠ 看不见** | `.ctx-menu { display: flex }` 压过 UA 的 `[hidden]` → 右键菜单关不掉。**凡设 `display` 的浮层必须自带 `[hidden]` 兜底**（守卫 7at） |
| 14 | `focusin` 无条件 reveal | 弹窗打开聚焦关闭按钮 → 提示自己冒出来。**提示只在悬停 / `:focus-visible` 显示** |
| 15 | 模块迁出后仍用绝对 URL 导入 | `/locales/…` 只有浏览器认，Node 侧 11 条单测 `ERR_MODULE_NOT_FOUND`。**改相对导入** |
| 16 | 交接包漏带 `locales/` | 102 → 99 文件，接手者拿到**没有文案**的程序。**交付白名单要显式列出「非 src 的内容资产」，并加断言** |
| 17 | 假声明「两次构建逐字节一致」 | `builtAt` 取当前时间必然不同。**可复现性声明必须参数化时间戳后实测** |
| 18 | 回收站元数据偏移算错 | 第一版偏移 8/24 且未裁尾 NUL → 得出「回收站里没有该记录」的反向结论。**解析二进制前先验证已知样本** |

## 十四、补充建议

1. **可访问性**：图标化按钮必须保留 `title` / `aria-label`。✅ 常态把关 —— `verify` 中 `aria-label` 相关判据 11 处，`browser_smoke` 逐控件查，纯视觉按钮为 0。
2. **测试同步**：改造控件形态（select→网格、新标签→弹窗、按钮→右键菜单、只读 chip→按钮）必须同步 `browser_smoke` 断言。✅ 四类均已落地，现 35 项。
3. **i18n 键闭包**：`verify` 的键闭包检查会把 JS 里任何 `a.b` 字符串当取词键 —— 新增语言包或写点分字面量时要留意豁免规则。
4. **数据迁移**：✅ 已实施（V0.1.0 四级解析）。判断从「不适用」改为「必须做」的转折点是**决定分发给其他用户**。
5. **安装态可写目录**：✅ 已实施 —— 数据与模板都按「可写则随项目、否则 `%APPDATA%/QingMan`」解析，模板**复制**播种。
6. **模板包以 `.md` 为主**：让 Skill / Agent 生态直接读取，工具导入时归一。
7. **一次性选型工具不落 `src/`**：预览 / 原型一律放 `docs/`，否则污染交付物并计入体积（`verify` 7f 以 `src.rglob("*")` 计数）。
8. **版本策略**：✅ 已定案（§七.2），不再是待议项。
9. **错误码闭环**：新增错误码须三处齐备（`error-codes.json` + 两语言包 + 调用方）。
10. **文档对齐三层**（《错误笔记》§三.93）：**指针化 > 生成块 > 陈述—锚点**。能指就不抄；确要抄就配锚点；`verify` 项数这类**自指数字无法自守**，只能指针化 —— 这也是本手册不再抄项数的原因。
