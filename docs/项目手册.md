# 青蔓 QingMan · 项目手册

更新日期：2026-10-09　|　当前版本：V0.0.1

---

## 一、项目概述

青蔓 QingMan 是一个**本地离线运行的目录结构设计工具**：可视化编辑目录树，一键在磁盘上生成真实目录。

与前代参考项目（E: 盘上的文心助手接续包）的根本区别：**从零重写、按专业架构拆分**，不再使用单文件 HTML。参考项目仅作功能与内容参考，代码不继承。

## 二、命名口径

| 项 | 取值 |
|---|---|
| 中文名 | 青蔓 |
| 英文名 | QingMan |
| 项目根目录名 | `QingMan`（英文，保证命令行与脚本兼容） |
| 界面显示 | 中文主标「青蔓」+ 英文副标「QingMan」 |
| 后端包名 | `server`，启动模块 `server:__main__` |

## 三、技术栈

| 层 | 选型 | 理由 |
|---|---|---|
| 前端 | 原生 HTML + CSS + ES Module | 零构建、零依赖、离线可用，改动即生效 |
| 后端 | Python 标准库（`http.server`） | 零第三方依赖；沿用参考项目路径，环境已具备 |
| 通信 | HTTP + JSON，仅监听 `127.0.0.1` | 本地单机，无跨域与网络暴露问题 |
| 运行环境 | Windows 10/11 + Python 3.8+ | 完全离线 |

## 四、架构与模块职责

```
src/
├─ web/
│  ├─ index.html           主界面骨架（不含版本号，版本徽标只在帮助页）
│  ├─ help.html            帮助页骨架 —— 纯空壳 + data-i18n 键名，一个中文都不写
│  ├─ css/
│  │  ├─ tokens.css        设计变量唯一来源（颜色/圆角/间距/字体）
│  │  ├─ base.css          基础元素：按钮、输入、chip、提示
│  │  ├─ layout.css        布局：顶栏 + 三栏 + 状态栏 + 提示条
│  │  └─ help.css          帮助页专属布局（复用 tokens/base）
│  └─ js/
│     ├─ main.js           主界面装配层：状态 → 视图 → 交互绑定 → 编辑态自动保存 → 自检
│     ├─ help.js           帮助页渲染层：填充占位 → 渲染分节 → 取后端版本
│     ├─ i18n/
│     │  └─ zh-CN.js       取词表：帮助页正文与分节结构的唯一数据源
│     ├─ core/
│     │  ├─ bus.js         事件总线（发布/订阅）
│     │  ├─ store.js       状态仓库（唯一状态源）
│     │  └─ api.js         后端调用唯一入口（其余模块禁用 fetch）
│     ├─ modules/
│     │  └─ tree-model.js  数据模型：增删改查 / 统计 / id 唯一性 / 文档序列化。纯数据，不碰 DOM 与网络
│     └─ ui/
│        ├─ tree-view.js   目录树渲染与交互（折叠态只存视图层）
│        ├─ inspector.js   右栏只读属性面板
│        └─ toast.js       轻提示
├─ server/
│  ├─ __main__.py          包入口（python -m server）
│  ├─ config.py            唯一配置源：路径、端口、开关、编辑态文档位置
│  ├─ dtree_core.py        纯逻辑：校验 / 统计 / 落盘 / 编辑态文档校验，不依赖 HTTP
│  ├─ routes.py            业务路由：收数据 → 核心逻辑 → 返回 dict（含 load/save_editor）
│  └─ app.py               HTTP 层：端口扫描、静态服务、分发、开浏览器
└─ shared/
   ├─ schema.json          前后端共享数据结构契约（含 editorDocument / editorNode）
   └─ error-codes.json     错误码 → 中文文案（前后端同一份）

data/                     运行时数据（**项目根**，不在 src/ 内）
└─ editor.json            编辑态文档：GET/PUT /api/editor 读写，进 .gitignore（§P0-7）
```

**分层铁律**

1. `tree-model.js` 不碰 DOM、不碰网络。
2. `tree-view.js` 只渲染、只回传事件，不改数据。
3. 所有网络请求必须走 `core/api.js`。
4. `dtree_core.py` 不 import HTTP 相关模块，可被 CLI/测试直接调用。
5. 路径与端口只在 `config.py` 定义，其余模块不得自行拼接。
6. **帮助页文案只写 `js/i18n/zh-CN.js`**：`help.html` 只留 `data-i18n` 键名，`help.js` 只查表渲染。`verify.py` 有「帮助页无硬编码中文」一项把关（§P0-3 L1）。
7. **编辑态文档的校验只在服务端定论**：前端 `fromDocumentNode()` 做容错转换，服务端 `dtree_core.validate_document()` 做严格判定。**不得只靠前端把关**（§P0-7 E3）。

**帮助页与主界面的关系**：独立页面，由主界面顶栏「帮助」按钮以**新标签**打开 —— 主界面内存里可能正握着一棵尚未落盘的目录树，同标签跳转会丢掉编辑态。

## 五、接口约定

| 方法 | 路径 | 说明 |
|---|---|---|
| GET | `/api/health` | 返回 `{ok, app, nameZh, version}` |
| POST | `/api/generate` | 生成目录。请求体见 `src/shared/schema.json` 的 `generateRequest` |
| GET | `/api/editor` | 读取编辑态文档。`doc` 为 `null` 表示尚无文档；文档损坏返回 400 `editorCorrupt` |
| PUT | `/api/editor` | 保存编辑态文档（**写操作，需防护头 `X-QingMan`**）。服务端重新校验，不合法拒写 |
| GET | `/*` | 静态文件服务，根目录为 `src/web/`，带路径穿越防护 |

`/api/generate` 请求体：

```json
{ "target": "E:\\我的项目", "root": "可选根文件夹名", "dryRun": true, "tree": { "目录": {} } }
```

树结构规则：值为 `{}` 对象 → 目录；值为字符串 → 文件（字符串即文件内容）。

**`/api/editor` 与 `/api/generate` 是两条独立的路**：前者读写编辑态（含 id），后者只读内存树并写目标目录。`treePayload()` 把内存树转成 `{名称: 内容}` 的落盘载荷（**不含 id**），`toDocumentNode()` 转成含 id 的持久化节点 —— 两者不可混用。

`/api/editor` 请求与响应：

```json
PUT  { "doc": { "schemaVersion": 1, "root": { "id": "d…", "type": "dir", "name": "根", "children": [] } } }
200  { "ok": true, "path": "…/data/editor.json", "savedAt": "2026-10-09T18:24:02+08:00", "bytes": 405, "stats": { "dirs": 1, "files": 1 } }
```

## 七、版本约定与流程（核心）

**SemVer 三段式：`V<MAJOR>.<MINOR>.<PATCH>`，从 V0.0.1 起。** 版本号唯一来源是项目根 `VERSION` 文件。
旧「V0.01 起、每次 +0.01」规则于 2026-10-09 作废。

| 递增 | 语义 | 例子 |
|---|---|---|
| `patch` | 修复、纠错 | V0.0.1 → V0.0.2 |
| `minor` | 新增功能 / 逻辑迭代 | V0.0.2 → V0.1.0 |
| `major` | 不兼容变更 | V0.1.0 → V1.0.0 |

**升版判据**：凡改动 `src/` 或交付契约 → 升版；纯文档、纯工具改动 → **不升版**，只在 `docs/任务进度.md` 记一条时间线。

### 7.1 五步流程

| 步 | 动作 | 命令 | 红线 |
|---|---|---|---|
| 1 | 在预览区开发 | 手动 | 绝不直接在 `src/` 上试错；`preview/` 按需新建 |
| 2 | 交付校验 | `python tools/verify.py preview/V<版本>` | **36 项**校验，不通过不落地 |
| 3 | 落地主线 | `python tools/promote.py --from preview/V<版本>` | 单向：预览 → 主线，只复制不删除 |
| 4 | 提交版本 | `python tools/store.py commit --note "说明"` | 落地后立即执行；写 blob 池 + 清单（同版本则追加修订） |
| 5 | 升级版本号 | `python tools/release.py bump --kind patch` | **改主线之前必须先 commit**；不升版则跳过本步，由 §P0-6 修订机制留回退点 |

> `--from` 缺省时按主线 `VERSION` 推导为 `preview/<当前版本>`，工具内不写死任何旧编号。

### 7.2 存储机制：内容寻址（借鉴 Git）

```
store/objects/<sha256前2位>/<sha256>      blob 池：路径即内容的指纹，相同内容只存一份
versions/<版本>/MANIFEST.json             版本基线（修订 r1）：路径 → 指纹 + 元数据
versions/<版本>/MANIFEST-r<N>.json        同版本后续修订（r2、r3…），不升版时留回退点
```

**修订引用语法**：`V0.0.1`（= 该版本最高修订）／`V0.0.1@r1`（基线）／`V0.0.1@r2`（第 2 次修订）。

`MANIFEST.json` 字段：

| 字段 | 说明 |
|---|---|
| `version` | 版本号，必须与目录名一致（`verify.py` 会校验「清单自洽」） |
| `revision` | 修订号；r1 为基线，r2 起为同版本追加修订（旧清单无此字段，按文件名补足） |
| `createdAt` | 提交时间 |
| `parent` | 上一**版本**，构成跨版本链 |
| `parentManifest` | 同一版本内的上一清单文件名，构成**修订链**（r1 为 `null`） |
| `note` | 提交说明 |
| `legacyAlias` | 旧编号别名（如 V0.0.1 的 `V0.01`） |
| `fileCount` / `files` | 文件数 ／「路径 → `sha256:` 指纹」映射 |
| `digest` | 清单摘要：对「路径 + 指纹」按路径排序后整体求 SHA-256（**改名也能检出**） |

命令一览：

| 命令 | 作用 |
|---|---|
| `python tools/store.py commit --note "说明"` | 提交当前 `src/` 状态；同版本已有清单时**追加修订**而非跳过 |
| `python tools/store.py checkout <版本[@rN]>` | 回退到指定版本／修订 |
| `python tools/store.py log` | 列出版本链（同一版本内按修订倒序） |
| `python tools/store.py diff <版本[@rN]> <版本[@rN]>` | 输出 改动 / 新增 / 缺失 |
| `python tools/store.py fsck` | 校验 blob 池完整性（文件名 == 内容指纹） |

**实测去重效果**：V0.0.1 → V0.0.2 的 23 个文件只新增 3 个 blob、复用 20 个（对象池 22→25，而非 45）。

### 7.3 版本隔离

- `preview/V<版本>/` —— 试运行区，完整可独立启动，与主线物理隔离。测试污染只可能发生在这一层。**平时为空**，需要试跑时才按版本新建（旧编号 `preview/V0.01/` 已于 2026-10-09 整体归档至 `legacy/preview-20261009/`）。
- `versions/V<版本>/MANIFEST*.json` —— 版本清单，**只增不改**。基线为 `MANIFEST.json`（r1），同版本后续改动追加为 `MANIFEST-r<N>.json`，**任何已有清单都不覆盖**（规则见 `docs/项目约定.md` §P0-6）。
- `store/objects/` —— blob 池，**只增不改**；同一内容永远不会写第二份。
- 纳入版本控制的文件：`src/` + `start.bat` + `VERSION`。`tools/` `templates/` `docs/` 为项目级资产，不进版本清单。
- 旧编号快照 `versions/V0.01/`（含 `SNAPSHOT.json`，MD5 口径）作为历史遗留原样保留，不再扩展。

### 7.4 回退

```bash
python tools/store.py checkout V0.0.1        # 按清单从 blob 池重建（取该版本最高修订）
python tools/store.py checkout V0.0.1@r1     # 精确回退到基线修订
python tools/store.py checkout V0.0.1@r3     # 精确回退到第 3 次修订
python tools/verify.py . --against V0.0.1    # 确认与清单完全一致
```

回退时「当前有、目标版本没有」的文件，先复制进 `store/.trash/<时间戳>/` 并**逐字节校验**，通过后才移除原文件 —— 全程不真删，可反复回退。

## 八、安全说明

- 后端仅监听 `127.0.0.1`，不对外暴露
- 不收集任何用户数据、不上传任何信息
- 静态服务做路径穿越防护（`resolve()` 后校验是否仍在 `web/` 内）
- 目录名校验：非法字符 `\ / : * ? " < > |`、控制字符、`.` `..`、Windows 系统保留名
- 请求体大小上限保护
- 生成操作需用户在前端主动点击
